# open-agent-robot

一個開放、可改造的多模態人形機器人 agent。機器人的**大腦與身體**以 ROS 2 節點跑在雲端一台 GPU 機器上;你的**筆電是它的眼、耳、嘴**;你的**瀏覽器是它的臉**。所有流量走同一條 SSH 通道。參考用例是**語音觸發的石頭剪刀布**(出拳與節拍同步)—— 它把整個迴路都逼出來:聽、看、想、說、動,而且全部要卡在一個硬實時的節拍上。

程式碼是為了將來搬上真機而寫的,而第六輪研究釐清了那到底需要什麼。虛擬與實體之間的接縫是一份 **DDS topic 契約,不是換一個節點**:`unitree_mujoco` 發 `rt/lowstate`、收 `rt/lowcmd`,與真的 Unitree G1 **位元組完全一致**,所以同一個 `hardware_interface::SystemInterface` 服務兩邊,切換收斂成兩個 xacro 參數。身體層目前還**不在**那個接縫上 —— 它在 render tick 上發 `/joint_states`,而這既是錯的**方向**(`/joint_states` 按 ROS 慣例是驅動器的回饋 topic,上真機會與 G1 driver 撞 topic),也慢了 4–43 倍。見 [`docs/research-round6-simreal-joint-mapping-2026-08-22.md`](docs/research-round6-simreal-joint-mapping-2026-08-22.md)。

> 現狀:端到端可用的 demo(普通話 / 英文 / 粵語語音、開放詞彙場景描述、猜拳遊戲、講故事、可打斷的說話)。研究級,不是產品。設計脈絡見 `docs/`。

## 為什麼長這樣

三個約束決定了架構,值得先講,因為它們解釋了那些乍看奇怪的選擇。

**1. 遊戲節拍不能等大模型。** 實測從機器到 Bedrock 的首 token 延遲 p50 約 0.9 秒 —— 用來閒聊很好,用來喊「石頭、剪刀、布 —— 出!」是致命的。所以系統明確切開:**反射層(System 1)**掌管節拍、停止詞、搶話,**絕不**呼叫 LLM;**思考層(System 2)**負責對話、場景理解、手勢選擇。使用者喊「停」時,是 `game_node` 裡的確定性關鍵詞比對讓遊戲停下 —— 不是一個被禮貌請求的模型。

**2. 筆電硬體才是誠實的介面。** 一個聽不見真實房間的機器人不值得做。一支小小的 C daemon 直接掌管麥克風、喇叭、相機(音訊用 miniaudio,相機用 libavdevice),因為延遲與雜音真正住在音訊路徑裡。它把 20 ms 的 PCM 塊與 MJPEG 幀透過一條 WebSocket 送出,幀頭 9 bytes(`[1B 型別][8B 擷取時間戳 µs]`)。

**3. 說話必須可以被打斷。** TTS **逐句**合成、逐句下傳,所以就算是長故事,第一句也在約 0.6 秒內出聲;使用者開口壓過機器人時會觸發清環,聲音當場斷在句中。這個「殺聲開關」也正是將來要做的**非同步輸出安全檢查**能不加延遲的原因(見 `docs/design-critique-memory-safety-*.md`)。

## 架構

```
MacBook                                  │  EC2 g4dn.xlarge (T4) — 單一 SSH 通道
─────────────────────────────────────────┼──────────────────────────────────────────
daemon/  (C)                             │  gateway/  ws_gateway.py   (WS ⇄ ROS 2)
  麥克風 16 kHz ─┐                        │      │
  相機 ──────────┼─ WebSocket /stream ────┼──────┤  speech/   asr_node   (FunASR 流式)
  喇叭 ◀─────────┘                        │      ├─          tts_node   (Kokoro 中/英 +
                                         │      │                       CosyVoice 粵語)
web/robot-view/  (瀏覽器)                 │      ├─ perception/ hand_node   (MediaPipe)
  MJPEG 身體視圖 + 事件 HUD ◀─────────────┼──────┤             detect_node (YOLO26 TRT)
                                         │      ├─ agent/    agent_node (Bedrock Converse)
                                         │      ├─ game/     game_node  (反射層)
                                         │      └─ body/     body_node  (MuJoCo + MJPEG)
```

同一張圖照比例畫、而且封包會動的版本:[`docs/architecture.svg`](docs/architecture.svg)
—— 裡面每個節點、每個 topic、每個缺口都由 `infra/ros_census.py` 生成,而它讀的是啟動器
而不是一份清單,所以一個不再被啟動的節點也就不再被畫出來。動畫用的是 CSS `offset-path`
(Chrome、Safari 16+、Firefox 122+);較舊的 renderer 會退化成同一張圖但封包不動,
除了動態以外什麼都沒少。想看**流程**——一個回合從耳朵到嘴巴、把已經出口的聲音攔下來、
說「忘記我說的 X」到底要付什麼代價——看 [`docs/workflow.md`](docs/workflow.md),
它那十張 Mermaid 圖跟同一份普查在兩個方向上都對過帳。

| 層 | 元件 | 是什麼 |
|---|---|---|
| 聽 | `speech/asr_node.py` | FunASR `paraformer-zh-streaming`,600 ms 塊,整句累積;半雙工閘讓機器人不會把自己的聲音聽寫進去 |
| 說 | `speech/tts_node.py` | Kokoro-82M(普通話+英文)逐句流式;偵測到粵語特徵字則路由到 CosyVoice 微服務(`speech/yue_server.py`) |
| 看 | `perception/detect_node.py` | YOLO26s 編成 TensorRT(T4 實測 161 FPS),限速到 5 fps,以 1 秒滾動窗聚合 |
| 手 | `perception/hand_node.py` | MediaPipe Tasks HandLandmarker;猜拳分類器**刻意忽略拇指**(每個人擺法不同) |
| 想 | `agent/agent_node.py` | Bedrock Converse、Claude Sonnet 5 global 推論設定檔;每輪附一張縮圖,支援開放詞彙的場景問答 |
| 技能 | `skills/loader.py` | 三級載入:每個技能常駐「名稱 + 一句話」(實測 96 個輸入 token);由**凍結的片語表**(而不是模型)命中時,才把本文附進當前這一回合;更深的檔案由模型透過 `read_skill_file` 自己取,該工具被圍堵在 `skills/` 之內 ——執行體與路徑柵欄在這裡,**登錄**在 `agent/tools.py`。這個切分是有理由的:當這個模組同時持有工具規格,「模型能碰到哪些工具」就由**知道技能的模組**回答,而第二個工具會被接在第一個旁邊 |
| 工具邊界 | `agent/tools.py` | 模型能呼叫的東西的**封閉登錄冊**,寫在還沒有第二個工具要跨過它之前。今天它宣告的**恰好只有一個**——`read_skill_file`,本地、唯讀——而那就是這個系統誠實的現狀:這台機器人能做的事是讀自己的技能檔,沒有別的。它現在就存在而不是跟第一個 MCP 客戶端一起長出來,理由是 MCP 客戶端回答「模型能碰到哪些工具」的方式是**在執行期問一台伺服器**,到那個時候離線套件就**結構上失去**斷言這個邊界的能力了。所以探索只能**縮小**登錄冊、永不放大:伺服器提供而這個 repo 沒有宣告的工具是一個 **finding**,而 `invoke` 對它回 `unknown_tool` ——就算它確實在活的 offer set 裡也一樣。dispatch 閘的兩邊都是**導出**的(執行體是名為 `_exec_<工具名>` 的模組函式),因為第二份「名字→函式」的 dict 是一個會過期的讀者,而在這裡過期的那個讀者是**一個模型叫得動、卻沒有人宣告過的函式**。一次呼叫有**六個**結果狀態,而其中**只有一個**(`refused`)能支撐「邊界守住了」這句話:原本那一個失敗字串把「模型編了個名字」、「伺服器不再提供」、「連不上」與「政策拒絕」印成同一行,而那正是**網路故障被記成保護**的方式。效果類別逐工具宣告,`MAX_EFFECT_HOPS` 是 **0**,與三次讀取跳轉**分開兩個數字**,因為三次讀檔與三個收不回來的動作是同一個整數在描述兩種完全不同的暴露 |
| 反射 | `game/game_node.py`、`safety/guard.py` | 機器人主導口令,判定窗 `[T−0.1 s, T+0.6 s]`;停止詞在**任何**狀態都生效 —— 而這是**簽名的性質**不是測試矩陣的性質:`guard.stop_requested(text)` 只收那句話,所以它**看不到**狀態,而節點則被結構式地驗證「派給它的位置在讀狀態之前」。每局冷卻。模型**只在舉手那一刻被問一次**,節拍本身只是把已經決定好的手打出去;這件事由測試從原始碼導出呼叫圖來**結構式**證明(節拍路徑根本到不了模型) |
| 對手模型 | `game/opponent.py` | order-2..4 條件轉移表,鍵在**使用者自己的**(手勢, 勝負)歷史——絕不鍵在機器人的出拳,那等於給反學習者一根槓桿去操縱「它被預測時所用的那個 context」。只在**anytime-valid e-value 閘**(Ville,δ = 0.05 是單一對手的**終身**誤開上界)判定這個人確實離開均勻時才利用,否則出公平的 1/3 硬幣。**已接進 `game_node`**:每局結果 fire-and-forget 發到 `/game/rps_round`,讓 `memory_node` 維持成唯一會寫盤的行程;累積表在啟動時由 **latched** topic 送回來,還原失敗的狀態一律整份拒絕而不做部分合併。`memory_node` 在 S3 已經存在,但目前只發佈檔案卡、還沒訂閱 `/game/rps_round`,所以今天沒有任何節點還原那張表:表每次開機都是空的,前 ~120 局實際上退回 1/3 硬幣(81 個 order-2 桶不可能被一場 20 局的 session 填滿——這是算術,不是調參選擇) |
| 憲法 | `safety/constitution.md`、`safety/guard.py` | 十條編號條文,以**執行期資料**而不是說明文件的身分出貨:任何已登記的條文 id 從檔案裡消失,載入器就拒絕啟動 —— 少一條邊界不是文件問題。系統提示由兩個函式各自組好、只串接一次:指令區(基礎提示 + 憲法)在前,加柵欄的資料區塊在後;而 `instruction_region()` 會**拒絕**任何帶柵欄標記或資料前言的參數,所以召回的文字沒辦法被夾帶進模型讀作規則的那一區。上限:口說 600 字、60 回合、3600 秒,手勢只能來自 `body/gestures.py` 那一份白名單 |
| 系統提示 | `agent/context.py` | 提示被組裝的唯一一個地方,而它存在的理由是上面那個接縫**是對的、但從來沒有被部署**:對 `safety/guard.py` 十四個公開名字做 AST 普查、比對全部生產檔案的結果是**十三個在測試之外沒有任何呼叫者**,而 `agent_node` 根本沒有 import 那個模組——它的提示是一個 725 字元的字面值加技能索引,憲法不在裡面。**一個沒有呼叫者的邊界不是邊界,而全綠的測試套件不會提到這件事**;會提到的是一次由生產檔案導出的呼叫者普查。現在節點以**fail-closed 且刻意不包在任何 `try` 裡**的方式載入憲法(技能目錄壞掉只讓機器人少一項能力,所以它降級;憲法載不起來等於每一條邊界條文都不在了),整個提示從這裡拿。**一個值落在哪一區,由它經過哪個參數決定**:憲法與技能索引是指令材料,檔案卡與檢索結果是資料,一個手上拿著召回命中的呼叫者**沒有任何參數**到得了規則區。區塊名字來自一個封閉元組,而 `data_region` 現在**拒絕**兩個會被算成同一個柵欄名的名字、而不是幫其中一個改名——兩個區塊一個名字,讀者無法說出任一個在哪裡結束。卡片區塊是常駐卡片與卡片路徑召回結果的**聯集**:兩邊在正常運作下就會不一致(一邊來自 latched topic,一邊讀 `profile.json`),取任一邊都會丟掉一條事實而且沒有任何地方說有東西被扣住了。降級的檢索路徑報給稽核日誌,絕不描述給模型。零 ROS、零 boto3、零時鐘、零檔案系統:機器人送出去的那個提示,是一台筆電可以重建並逐位元比對的東西 |
| 輸出守衛 | `safety/output_guard.py`、`safety/output_guard_harness.py` | 對機器人**即將說出口**的句子做的句級檢查,而它的異步是**構造出來的**,不是約定的:`offer()` 標註成 `-> None`,一條測試斷言它的函式體裡沒有任何帶值的 `return`,所以呼叫端沒有地方可以等,一個串行守衛在這個 API 裡**不可表達**。裁決從後來的 `verdict(uid, index, …)` 進來,對號的是**說話者命名的那個 span** —— 永遠不是守衛自己切的句子,因為斷句邊界已經有兩個擁有者(Kokoro 的 pipeline、粵語的標記字元切分),第三條規則的後果是中斷打到錯的句子。一份裁決可以宣稱什麼,取決於已經被聽見多少,所以可聽度是四個值而不是一個布林:裁決比第一塊音訊早到、音訊開始了而中斷把它切掉(**這是正常情況**,我們自己量到的分類器最壞值是 921 ms)、播完了所以守衛什麼都沒擋住、以及說話者自己把句子丟掉了 —— 而最後這個必須**被告知**,因為從守衛裡面看,「還沒出聲」與「永遠不會出聲」是同一個「沒有音訊」而結論相反。只有在還有東西可中斷時才發中斷,而稽核記錄只有在**真的發出過中斷**時才寫 `blocked`;把一個播完的句子併進「擋下」,就是讓報告在守衛什麼都沒做的時候顯示滿分的那個謊。分類器失敗是 `errored`,不是放行。2.0 秒的期限是**我們自己量到的最壞值的 2.2 倍**,不是一個挑出來的整數,而一條測試從證據 JSON 把它導出來 |
| 紅隊集 | `tests/fixtures/redteam.jsonl` | 50 條凍結的、機器人不該說出口的**候選輸出** —— 38 條中文、12 條粵語、7 個類別 —— 離線由三個故意會說謊的分類器分級,所以每一個退出碼都不用網路就驅動得到。它拒絕做兩件事:一是**把類別池化**,因為 `identity_denial` 與 `boundary_override` 在輸出側**完全沒有執行者**(內容過濾器沒有這兩個類別,而 `PROMPT_ATTACK` 只作用於輸入側),把它們平均進另外五個有執行者的類別,等於用別的類別的成績蓋掉一個缺口;二是**算粵語的 block rate**,因為官方不支援這個語言,所以一條被擋下的粵語句子是關於一個字串的一次觀察。harness 有四個退出碼,而**0 今天不可達** —— 一條測試對真實的凍結集斷言這件事,因為 0 是讀者會引用的那個數字。按規則 3,凍結集 0 逃脫是**曝露的下限**,永遠不是保證;集合只增不減 |
| 檔案卡 | `memory/profile.py`、`memory/memory_node.py` | ~17 條手寫事實,落在**封閉謂詞集**裡,開機時以 `transient_local` 在 `/memory/profile` 發佈一次,所以後啟動的節點不用往返也拿得到。它是**唯讀種子直到 S5**,而那個鎖放在單寫者裡(`store.PROTECTED_SNAPSHOTS`),不放在這個模組:寫入 API 是 `Store.write_snapshot`,一個只是「自己不去呼叫」的讀取端只約束得到經過它的那些呼叫者。`unlock_for_s5()` 是唯一具名的通道。鎖的理由是來源可追:語義事實必須指名它來自哪些 episode,刪除 episode 才能連帶刪掉它產生的東西,而 S4 之前根本沒有 episode——現在寫進去的事實會是任何刪除都到不了的事實。350 token 的常駐預算在開機時對**真實那張卡**執行,不只是對 repo 附的示例斷言;超預算讓節點開機失敗而不是印一行警告:它是**每回合都要付、付到行程結束**的成本 |
| salience | `memory/salience.py` | 一個 turn 值不值得記住:`0.4·明示評價 + 0.3·新穎度 + 0.2·被要求記住 + 0.1·長度`,四項全部只由**文字與意圖**算出。音高、音量、語速在 EU AI Act Art 3(34) 下都是行為特徵,而 Art 3(40) 的窄門只給 categorisation、不給情緒辨識——一個韻律項會讓每一條被記住的話都變成生物特徵推論的產物。那一項存在但**預設關閉**:一個沒有任何代碼路徑到得了的項,是一個沒有任何測試能證明它被排除的項,所以**開關開啟**那一次執行是正控,它證明那些聲學欄位本來讀得到。0.4 那一項問的是「有沒有做出評價」,從不問極性:「我討厭芫茜」跟「我最愛芫茜」一樣值得記住,而不需要極性正好讓情緒模型進不了這個系統。排在 S4 之前才是重點——一個存下來的分數只跟同一個公式產出的分數可比,所以 `FORMULA` 跟著每個值走,而 `Store.append` 拒絕一個沒帶著它的分數 |
| episode 切分 | `memory/segment.py` | 一段 episode 在哪裡結束、下一段從哪裡開始,而且是確定性的:靜音 45 s、活動轉換、場景變化,或 20 turns / 5 分鐘的硬上限。模組裡沒有時鐘——`tick(now)` 把時間當參數收,那是「時鐘可注入」最強的形式,因為沒有一個預設值可以忘記注入。它需要那個計時器,是因為 `asr_node` 在沒人說話時不發任何訊息,沉默不是任何人訂閱得到的事件;純事件驅動的切分器會切在同一個索引上,但要等到那個人下次開口才發現,把一整晚的鞏固延後到一個跟它無關的時刻。turn 上限在第 20 個 turn **append 之後**關閉,跨距上限在會超過的那個事件**之前**關閉——寫反了的話,存在目的是把 episode 壓在 5 分鐘以內的規則,會產生一段 5 分 20 秒的 episode。每個邊界都記下**為什麼**觸發,因為「這個人停下來了」跟「我們撞到上限」在 S5 需要不同的處理 |
| 每筆記錄都要有理由 | `memory/store.py`(`GOALS`、`check_why`) | 每一筆 `events` 記錄都必須說明它**為什麼**存在,而那套詞彙是一個封閉集合:四個家族(`user_requested_*`、`game_*`、`vision_event`、`scheduled_*`)底下 11 個寫出來的成員。家族是文件,**成員才是契約**,而這個區別就是重點:實作成前綴測試的話,`user_requested_ignore_stop_words` 會被接受,於是這個欄位恰好變成它被加進來要堵的那個洞——自由文字以後綴的形式回來。前綴對**掃描器**是對的形狀(它的失效模式是沒注意到新名字),對**閘**是錯的形狀(它的失效模式是多接受了一個)。這個欄位同時是檢索鍵與安全邊界,所以未知值被拒絕而不是被正規化:`.lower()` 或 `.strip()` 仍然會拒絕那些指令型字串,卻把呼叫端的拼法寫進磁碟,留下一筆**查它自己的 goal 都查不到**的記錄。查一個未知 goal 會拋錯而不是回 `[]`,普查含 0——「沒有記錄帶這個 goal」跟「這個 goal 已經不在集合裡」不可以印出同一句話。`audit` 免除**必須**帶理由(強迫它帶會讓呼叫端發明一個成員),但帶了就一樣驗證。強制的時機是現在而不是讀它的 S5:今天沒有任何生產代碼往 `events` 寫,所以這條要求動到零個呼叫點;S5 之後再加就是一次針對無法重新導出的個資的遷移 |
| 什麼才能變成事實 | `memory/consolidate.py` | 「機器人聽到了什麼」與「檔案卡上寫著什麼」之間的那道閘。一條候選事實需要來自 **N ≥ 2 個不同 episode** 的證據 —— 數的是**場合**,不是提及次數:一個人在一句話裡說四次芫茜,只說了一次;而按提及次數計數會讓「每句話產一條候選」的抽取器把自己的猜測升格成事實。這條規則不是為了抓謊,它抓的是**聽錯**、假設語氣(「如果我討厭芫茜的話」)、以及轉述別人的話。偏好與界線(`likes`、`dislikes`、`allergy`、`boundary`、`pronouns`、`name`)完全不收**推論**來的證據,而推論來的證據也不能替單一次自述補上第二個場合;偵測器對房間本來就觀察得到的(`device`、`location`、`household`、`routine`、`pet`、`language`)可以推論,而那張表把 18 個謂詞全部寫出來,不用預設值。trust 是證據的**種類**而不是數量:`confirmed` 要求本人說過「是」,永遠不會由重複次數得到 —— 否則同一個聽錯重複夠多次就變成已確認的事實。值的比對逐位元,而模糊比對器是**刻意不做**的:一次錯誤的合併不只是存錯值,它**製造出**這條規則所要求的第二個場合,而一個閘如果它的證據可以由它所要守的東西合成出來,就不是閘。每條被接受的事實都帶著 `source_episode_ids`,已排序去重,而且每個 id 都必須解析得到;id 由該 episode **首筆記錄的 store 序號**導出,絕不由位置導出 —— 因為刪掉前面一個 episode 之後,由位置導出的 id 會**成功解析到另一個 episode**,而由序號導出的會懸空,而只有懸空的參照才找得到、動得了,那正是 S5 接下來要蓋的刪除路徑唯一能站得住的地基 |
| 檢索 | `memory/recall.py` | 對磁碟上的記憶開五條路徑 —— 檔案卡、`why.goal` 結構化過濾、事件日誌上的 BM25、episode 嵌入上的 cosine、以及 RPS 表 —— 全部在 **150 ms 期限**之內。每條路徑回傳一個**狀態**,取值 `(ran, no_artifact, no_encoder, deadline)`:一份空結果有四個互不相同的來源,而只有其中一個能支撐「沒有東西符合」這句話 —— 沒有編碼器、磁碟上沒有 artifact、期限用完了,這三個都是**根本沒跑的路徑**,而它們恰好就是級聯刪除測試要殺的那個突變體。所以「被刪的 episode 零命中」只有跟 `ran` 一起才成立。路徑集合是**導出的,不是列出來的**:一條路徑只能以 `_run_<name>` 方法的形狀存在,而一條測試把那個集合跟登錄冊**兩個方向**都比一次,於是沒登錄的新路徑跟沒方法的登錄都會紅;每條路徑聲明自己讀哪些檔案,而那份聲明會跟**磁碟上真的存在的** artifact 對帳,因為寫入 API 收任何一個普通檔名。一筆沒有 episode 的命中分成兩種 —— 手寫的**種子**事實本來就在級聯之外,而**孤兒**是該指向某個 episode 卻沒指到的;把兩者併成同一個 `None` 會遮掉最便宜的作弊法:刪掉 episode 的條目卻留著它的事件,於是每一個對它的參照都指向「無」,按歸屬檢查會讀到零命中,而文字還檢索得到。卡片事實**每個來源 episode 報一筆命中**,不是只報第一筆,否則刪掉第二個來源時卡片會回報乾淨,而那一列還在引用它。分數**永不跨路徑融合**:BM25 沒有上界而 cosine ≤ 1.0,一份按分數排的合併清單是按一個不存在的量排的,而那個校準從來沒被量過 —— 排序只在路徑之內,`k` 也逐路徑生效。不做行程內快取,因為一份撐過刪除的索引**就是**那個突變體 |
| 排序對照 | `memory/rank.py`、`memory/rank_harness.py` | 對一份檢索結果的三個排序政策—— **衰減**、**重要性剪枝**、**只改排序不刪除** —— 好讓「我們偏好哪一個」是比出來的,不是宣稱的。一支臂是**對 `Result` 的政策**,永遠不是對 `Hit.score` 的編輯:分數跨路徑不可比,而 `Hit` 不可變,所以這件事由型別強制。真正承重的規則是**缺席資料是一層,不是預設值**:一個沒有 `end_ts` 的 episode,填 `now` 會讓它變成全店最新;填 0 會讓它低過衰減地板而從答案裡消失。所以什麼都不填預設值:六個新鮮度狀態(`dated`、`undatable`、`future_ts`、`no_episode_by_design`、`lost_attribution`、`no_entry`)與五個重要性狀態(`scored`、`no_salience`、`other_formula`、`unscorable`、`no_record`),每條路徑再切成一個可重排、可丟的**可比較層**,與一個留在檢索器自己順序裡的**不可比較層**。`other_formula` 刻意不等於 `no_salience`:一個需要重新評分,另一個需要「哪個公式才是正典」這個決定,而把兩個公式的數字放在一起比,是排序器必須**注意到**的事而不是拿來平均的事。這套測試證明不了的是**哪一支更好** —— 那需要 T-F1 的 30 條凍結查詢,也就是一天真實日誌加一次人工標註,兩者都不得編造。所以 `quality` 是狀態 `NO_LABELS` 而不是一個數字,要求一個有標註的分數會直接拋錯,而 harness 有**四個退出碼**而不是一個布林:0 已下結論(今天不可達,而且必須維持不可達)、1 畸形、2 良構但仍然無法下結論(**這就是今天的狀態**)、3 根本跑不起來。三支臂完全一致,正是一次空跑從外面看起來的樣子,所以零查詢與零命中都被數、也都會拒絕。衰減是時間的函數,所以時鐘是注入的、而且寫進 JSON:同一份 store 逐位元重放得出來 |
| 記憶寫者 | `memory/store.py` | `memory_node` 背後的單寫者 append-only 日誌。一條寫者執行緒同時服務 `events` 與 `audit` 兩個 stream —— 同一個保留期、同一條級聯刪除路徑,所以它們不可能互相不一致。序號在鎖內取得、以**高水位**發佈(一批可能倒序入列);序列化失敗的記錄被拒絕但**不消耗序號**;快照用 `os.replace` 換名,所以持有舊檔的讀者繼續讀到完整位元組;寫者執行緒死掉時 `flush()` 拋錯而不是無限等待 |
| 身體 | `body/body_node.py` | MuJoCo 運動學木偶(Dex3-1 三指手:拇指 3 自由度、食指 2、中指 2,單手 7 個),以 MJPEG 串到瀏覽器 |
| 傳輸 | `daemon/main.c`、`gateway/ws_gateway.py` | 單一 WebSocket、二進位分幀;音訊優先於視訊,兩者都有流控 |

## 快速開始

前置:一個開通 Bedrock 模型權限的 AWS 帳號、登入好的 AWS CLI、macOS + Homebrew,以及 `brew install ffmpeg libwebsockets`。

```bash
# 1. 開一台上鎖的 GPU 機器(只開 SSH、只放你的 IP、強制 IMDSv2、
#    加密根碟、實例角色只給 Bedrock invoke)。可重複執行。
infra/provision.sh            # 產生 infra/ssh_config 與 infra/local.env(皆已 git-ignore)

# 2. 在機器上安裝整套環境。三個階段,在機器上自己跑:
#      ./setup-ec2.sh driver   NVIDIA 驅動,跑完要重開機
#      ./setup-ec2.sh stack    ROS 2 Jazzy + Python 環境 + G1 身體模型
#      ./setup-ec2.sh yue      粵語 TTS 的獨立 venv(不需要粵語可略過)
infra/setup-ec2.sh            # 見腳本檔頭

# 3. 啟動機器人的大腦與身體(節點表裡的每一個,含 `yue`)
ssh -F infra/ssh_config robot 'open-agent-robot/infra/run_ec2.sh start-all'

# 4. 開通道、編譯並啟動 daemon、打開它的臉
ssh -F infra/ssh_config -N -f robot
cd daemon && make && ./oar-daemon
open web/robot-view/index.html
```

然後對筆電說「我們玩石頭剪刀布」或 "let's play rock paper scissors"。
完整流程與排錯:[`docs/DEMO.md`](docs/DEMO.md)。

## 測試

```bash
pytest -m "not mutation"   # 每次存檔跑
pytest                     # 每個 PR 跑:加上具名突變體
pytest -m mutation         # 只跑突變體(2026-08-26 量到 333 個案例)
infra/check_deploy.sh      # repo 裡的每個節點,runner 真的會啟動它嗎?
```

讀這套測試之前有兩件事值得先知道:

**這裡沒有任何一個測試用模型當判官。** 判官當獎勵訊號時,**量到的**通過率從 0.72 升到
0.94,而真實正確率平在 0.20;嚴格的三判官集成仍然接受 55% 的錯誤答案。所以任何需要語義
判斷的性質,要嘛降維成機器可檢查的代理量,要嘛移出 CI 進人工驗收。

**每一條斷言都配一個它必須殺掉的具名突變體** —— 突變體產生位元相同的輸出,代表我們測錯了量,
不代表代碼安全。每一輪突變測試還要跑一個必須綠的**無突變對照**,因為壞掉的 harness 也會報成功。
上面那句話裡的「每一條」本身也被檢查:一個 meta 測試**推導**什麼算是突變體施加器
(改寫原始碼文字**而且**把結果變回程式),呼叫它卻沒帶 `mutation` marker 就紅。
它抓到兩個模組的突變體 `pytest -m mutation` 從來沒有跑過。
`infra/check_deploy.sh` 分三個退出碼是同一個道理:0 乾淨、1 有發現、**3 是守衛跑不起來** ——
一個跑不起來的守衛,絕不能回報「乾淨」。

完整契約(含尚未實作的項目)在 [`docs/test-design.md`](docs/test-design.md)。

**那份契約自己有三條通過標準是錯的,而測試把它說出來了。** 原本要求「拿掉信賴閘之後,
均勻對手那一案必須紅」——但猜拳是零和且對稱的,面對均勻對手,**任何**策略的期望分數
恰好是 0。那條標準在原理上就做不到,不是沒實作;判別斷言因此改成 Ville 界
(曾開過閘的 seed 比例:設閘 3/100,未設閘 100/100)。第二條標準預測閘面對會適應的
反學習者會關著。實測是 **71% 的回合開著,而模型還贏**——因為迴路是閉合的:
機器人的出拳是使用者自身歷史的函數,所以一個對機器人反應的對手,**因此就是**
在對那段歷史反應。第三條要求「節拍的 p95 抖動 ≤ 現值 + 5 ms」,那是一條計時斷言,
而一個會因為筆電忙而變紅的測試,兩天內就會被加上 `skip`。它改成了一個在任何負載下
都給同一個答案的**結構式** oracle:從 `game/game_node.py` 導出方法層的呼叫圖,
取節拍入口的可達閉包,與「碰得到模型」的方法集合取交集,斷言那個交集是空的。
抖動仍然要量,只是永不斷言——`docs/evidence/track-b/arm-cost.json` 記著
2000 次呼叫在一張由 300 局真實回合暖機的表上:p50 0.0082 ms / p95 0.0113 ms /
max 0.1137 ms,也就是一個 20 ms 節拍週期的 **0.57%**,而且它在一條節拍根本不會走的路上。
三處修正與逼出它們的量測都在契約的 §2.H。

那個結構閘同時是「為什麼每條斷言都要配突變體」最清楚的例子。它的第一版拿呼叫圖的閉包
去對照一份**手寫的**「允許碰模型的方法」名單——而那個把 `self.opponent.predict()`
**inline** 寫進節拍 callback 的突變體直接穿了過去,因為 inline 不會產生任何新的**具名**
觸碰者。交集的兩邊都必須是導出來的。這件事在複查裡完全看不出來;是突變體抓到的。

## 設計記錄

**要問「設計是什麼」,只看這一份:**[`docs/design.md`](docs/design.md) 是它唯一的權威陳述 ——
五個承諾各自真的接到哪一層、System 1 / System 2 的分工與逼出它的那個量測、
不變量的封閉清單(每一條指名失去它時會紅的那個測試),以及這個專案刻意不蓋什麼。
最後那一節把**被證偽**、**延後且有具名前置條件**、**未被評估**分開寫,
因為一份把三者都寫成「我們不做 X」的文件,會告訴下一個讀者證據已經蓋棺,而事實上沒有。
排程在 [`docs/plan.md`](docs/plan.md);測試契約在 [`docs/test-design.md`](docs/test-design.md)。
哪份文件取代或部分推翻哪一份記在 [`docs/INDEX.md`](docs/INDEX.md) ——
`docs/` 底下每一份文件一列,狀態取自封閉集、附一句具名理由,

- [`docs/research-round7-rl-and-two-tier-2026-08-22.md`](docs/research-round7-rl-and-two-tier-2026-08-22.md) —— 這個 agent 該不該加強化學習?本機小模型該不該和遠端大模型分工?兩個並行研究工作流、213 次 agent 呼叫、回收 245 條主張(原始證據在 [`docs/evidence/round7/`](docs/evidence/round7/))。兩個答案都是**不該,而且理由是推導出來的而不是列舉出來的**:**RL 只在獎勵由「非 LLM 感測器」量測的地方可接受**,這一條就排除了我們原本想到的每一個介入點;而兩級模型**只以延遲遮蔽的形式存活**,不是以路由的形式 —— 路由需要一個比大模型更便宜、又能可靠知道「我不知道」的機制,而這個機制沿整條鏈被證偽(路由高原:10 倍資料只換到 +2.13 pp;熵路由器在 TextWorld 上升級率 **0.0%**;10% 風險界下**零**組可認證的模型配對)。與 RL 無關、**今天就該用**的兩條:問模型「你確定嗎」會讓準確率掉最多 **27%**,並讓它在 42–98% 的情況下錯認自己有錯,而且**對→錯的翻轉多於錯→對**;硬 schema 解碼可以做到 **100% 合法而可執行率從 91.5% 掉到 48.0%**,結構驗證器抓到的比例是 **0%** —— 所以推理放開、約束放到最後。這一輪同時修正了我們自己先前的兩條主張(§8)。

## 安全姿態

- 機器上只開 22 埠,且只放行操作者當前 IP,其餘全走通道;強制 IMDSv2、根碟加密、實例角色只有 `bedrock:InvokeModel`。
- 帳號相關的值(實例 id、公網 IP、金鑰路徑)由 `provision.sh` 產生到 git-ignore 的檔案裡;版本庫中不追蹤任何帳號專屬資訊。
- 原始麥克風音訊與相機幀默認**永不落盤**。每輪對話會送一張縮圖到 Bedrock —— 這是第三方傳輸,任何部署都必須向使用者明示。
