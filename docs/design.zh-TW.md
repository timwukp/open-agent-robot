# open-agent-robot —— 當前設計

這個檔案是**「這個系統今天想成為什麼」的唯一權威陳述**。在它存在之前,答案住在一台筆電的
`~/.claude/plans/` 裡,加上 `docs/` 裡六份研究文件與一份設計審視 —— **合計 191 KiB** —— 按日期排列。
2026-08-25 量到:**那六份研究文件裡有四份完全沒有任何「已被取代」的標記** ——
而四份裡的一份是第四輪:它的 §0 build order 被 `docs/design-critique-memory-safety-2026-08-22.md` §4
整段取代,它的記憶選型被 `docs/research-round5-memory-safety-2026-08-22.md` 在自己的開頭重新回答。
一個外部貢獻者要回答「現在的設計是什麼」,
得讀那 191 KiB 並且自己判斷哪些結論已經過期。對一個自稱 open / hackable 的東西,這是真的缺口。
所以這個檔案存在,而研究輪次回到它們本來的身分:**證據,原文保留,不是一份要你自己用手 diff 的設計紀錄。**

閱讀順序:設計看這一份,接下來要蓋什麼看 [`docs/plan.md`](plan.md),測試契約看
[`docs/test-design.md`](test-design.md)。哪份文件取代或部分推翻哪一份記在
[`docs/INDEX.md`](INDEX.md),而下面的 §4.4 帶著那三條「就算沒開索引的人也必須讀到」的撤回。

有兩條規則管著這個檔案,因為設計文件是一個 repo 裡最容易腐爛的檔案:

1. **每一個關於「跑起來的系統」的主張都要指名它的證據** —— 一個檔案與行號、一個
   「主張不成立時會紅」的測試,或者一個帶日期的量測。沒有證據的主張要標成主張。
2. **「不做 X」是三種不同的狀態,永遠不是一種。** 被證偽、延後且有具名前置條件、
   未被評估,這三句話不一樣;把它們塌成一句的文件,會告訴下一個讀者證據已經蓋棺,
   而事實上沒有。§4 刻意把它們分開。

## 1. 五個承諾,以及每一個真的接到哪一層

這個 repo 裡最有意思的數字不是「它會做什麼」,是**它承諾的東西與一個跑著的行程真的到得了的東西之間的落差** ——
而這個落差是**由閘導出的,不是靠人記得**:`infra/wiring_census.py` 讀每一個 python 檔案,
報出每一個只有 `pytest` 到得了的接縫,並且把結果拿去跟 `infra/dormant_seams.tsv` **兩個方向**對帳。

| # | 承諾 | 到得了哪 | 證據 |
|---|---|---|---|
| 1 | **它聽得到、看得到、說得出話、會動 —— 而且會揭露自己是機器** | **端到端跑得起來。** | 展示手冊 [`docs/DEMO.md`](DEMO.md);Art 50(1) 由 `gateway/ws_gateway.py:105-119` 經 `safety/disclosure.py` 從 `/speech/say` 說出來,**路徑上沒有 LLM**,由 `tests/test_disclosure.py`(T-E1)斷言 |
| 2 | **它記得你** | **代碼完成,執行期休眠。** `agent/context.py:261 assemble()` 收 `card` 與 `recall`;`agent/agent_node.py:83` 兩個都沒傳,所以 `memory/recall.py`、`memory/consolidate.py`、`memory/salience.py` 在執行期一行都不跑,而 `memory/segment.py` 沒有任何節點載入。 | `infra/dormant_seams.tsv` 三列(`assemble(card=)`、`assemble(recall=)`、`memory/segment.py`),加上 `infra/graph_gaps.tsv` 的 `/memory/profile`。由 R1.1、R1.3、R1.4 接上 |

**誠實的總結是一句話:** 承諾 1 跑得起來,承諾 2–5 蓋好了、離線測過了、沒有接上 ——
六個休眠子系統是 **3,492 行生產碼 + 5,488 行測試碼 = 8,980 行**,對照 2026-08-26 整棵樹的
35,507 行 python,是 **25.3%**(一輪前對 34,794 行讀到的是 25.8% —— 見下)。

那個百分比是這一頁上**最弱的數字**,而它為什麼弱值得寫下來:**它的分母是整棵樹,
所以在任何地方多寫測試都會讓休眠比例下降,而什麼都沒接上** ——
而它已經在兩輪之內掉了兩次,而一個子系統都沒接上:R0b-1 的普查把它從 26.6% 推到 25.8%,
靠的是多出 1,042 行(`infra/wiring_census.py` 454 + `tests/test_wiring_census.py` 588);
R0b-2 又把它推到 25.3%,靠的是再多 713 行(`infra/doc_status.py`、
`tests/test_doc_status.py` 與擴大的那幾個閘)—— 而這個 PR 談的是**文件狀態**。
一個「寫一份關於文件的文件」就會變好的數字,量的不是它名字說的那件事。
會**乖乖表現**的數字是**接縫數**:`infra/wiring_census.py` 今天報 **43**,
`infra/dormant_seams.tsv` 43 列全部帶具名理由,而 R1 的每一個 PR 都被要求至少刪掉一列。
引用接縫數;把百分比當背景。

**「到得了」在這裡是什麼意思 —— 要講,因為它比聽起來窄。**
可達性是在 `infra/run_ec2.sh` 啟動的那些行程上、用**靜態呼叫圖**算的。
一個模組被 import 而且被呼叫,不代表在真機上有訊息流過它 ——
那是 `docs/test-design.md` §3 的 L4,而 L4 被擋住(§6)。反方向也一樣:
一個被報成 unreached 的檔案是「**在這棵樹裡**沒有靜態呼叫路徑」,不等於它永遠不執行;
`importlib` 或字串反射會直接繞過這個普查,而這棵樹今天沒有那樣的呼叫點。

## 2. 兩個系統,以及為什麼這個分工是量出來的而不是品味

架構的核心選擇是:**反射層永遠不呼叫語言模型。** 這不是一個關於 System 1 / System 2 的哲學立場,
是 `docs/day0-measurements.md` 的算術。

從那台機器量到 Bedrock,Haiku 4.5 的首 token 時間是 **p50 900 ms(min 645、max 1270、n=10、
`ConverseStream`、`global.` inference profile —— 在 ap-southeast-1,直接的 model ID 不能 on-demand 呼叫)**。
一局猜拳的節拍大約 500 ms。所以任何「節拍要等模型」的設計,在第一個使用者出現之前就已經壞了,
而且再怎麼調 prompt 都救不回來。就是這一個數字逼出了這個分工:

| 層 | 負責 | 永遠不做 | 由什麼強制 |
|---|---|---|---|
| **System 1 —— 反射** | 節拍計時、停止詞、搶話、手勢白名單查表 | 呼叫 LLM。不是「盡量避免」,是**做不到** | `tests/test_guard.py::test_the_stop_reflex_needs_no_boto3_even_lazily` 把 `boto3` 換成一個「任何屬性存取都拋異常」的物件再跑停止路徑 —— 光做靜態 import 掃描不夠,因為函式裡一句 lazy `import boto3` 會通過那種掃描 |
| **System 2 —— 審議** | 對話、描述場景、**選**手勢、講故事 | 擁有任何比它自己更短的期限 | 中斷路徑:`/speech/interrupt` → `T_FLUSH` 才是讓「非同步的安全檢查」變得付得起的東西 |

這個分工有兩個結果值得寫下來,因為它們看起來像意外:

**輸出守衛必須是非同步的 —— 而這個前提是借來的,後來被量了。**
最早這個設計靠的是第三方對 Bedrock Guardrails 的 client-side 數字:p50 749 / p90 907 / max 1837 ms,
**n=15**。一整套安全架構跟著別人的 n=15 走,值得查一次,所以
`safety/guardrail_latency_harness.py`(T-K3)在我們自己的 region 量了 `apply_guardrail`,
source=OUTPUT、每個語言組 n ≥ 30、整套跑兩次。結果:**p50 415.8–435.4 ms、p95 498.7–531.6 ms**
(pooled 每組 n=60)—— 比借來的數字**低約 44%**。

**設計存活下來了,而「為什麼存活」值得說清楚。** 三個語言組**都還是超過** S7 的 400 ms 預算,
而非同步設計的前提只需要「這個呼叫大到不能跟說話串在一起」,不需要任何特定的值。
所以 R1.6 把裁決走**既有的** `/speech/interrupt` → `T_FLUSH` 殺聲路徑,而不是拿它去閘住說話:
機器人先開口,裁決說不行就在句子中間被切斷。那個殺聲開關本來是為搶話蓋的;安全免費搭它的車。

那次量測教了兩件事,而兩件在「只跑一次」的設計裡都看不見:

- **沒有哪個語言比較慢。** 語言組之間的 p50 差距是 19.6 ms;**同一組**重測的 95% 上界是 40.6 ms。
  差距落在噪音裡,所以這份資料**不支持**任何「粵語或國語比較貴」的說法。
  比較的標尺必須是重測區間的**最寬界**,永遠不是它的點估計 ——
  純噪音拿點對點比,幾乎任何差距都會看起來是真的。
- **護欄 tier 是從控制面讀出來的,不是寫下來的。** 照直覺建護欄會得到 Classic tier,
  而 Classic 只支援 en/fr/es —— 一個這台機器人**一種都不說**的 tier。
  原本的斷言 `evidence["tier"] == "STANDARD"` 對上的是 harness 自己寫進去的字面
  `"tier": "STANDARD"`,所以它永遠綠,而底下量的是錯的 tier。

還有一個會改變預期的延遲結果:`effort:"low"` **買不到更快的首 token**
(+48.3 ms,95% CI [−6.5, +95.8],跨過 0)。這個參數**確實被讀了** —— 它縮短的是**生成長度**。
對句級流式 TTS 來說,它買到的是更短的回合與更低的輸出成本,不是更早開口。

**語音是逐句送出去的**,而這正是「中斷」有意義的前提 —— 你沒辦法 flush 一段被當成一整塊合成出來的話。
首次出聲的算術在兩個語言之間不對稱,而這個不對稱是量到的:
國語走 Kokoro-82M 首包 **~0.15 s**,所以首次出聲大約落在 900 ms + 150 ms ≈ **1.05 s**;
粵語走 CosyVoice-300M-SFT 首包 **3.63 s**,是 Kokoro 的 24 倍。
就是這個落差讓粵語的固定台詞(問候、對局吟唱、停止確認)被**預先合成進短語快取**,
只有新句子才付那 3.63 s。這個 repo 從來不宣稱粵語**受到保護**,只宣稱它會被說出來 ——
`tests/test_guard.py` 與 T-G4 兩邊都釘住這個區別,因為對一個 Guardrails 沒有列出支援的語言
回一個「很快」的呼叫,是最容易不小心暗示「有保護」的方式。

## 3. 不變量 —— 封閉清單

這些是這個系統不准失去的性質。每一條都指名「失去它時會紅」的那個測試。
這份清單是**封閉的**:不在上面的東西是設計偏好,不是不變量,可以在不經過這裡討論的情況下換掉。

| # | 不變量 | 它在哪裡被創造 | 失去它時什麼會紅 |
|---|---|---|---|
| I1 | **單一寫入者。** 只有 `memory_node` 落盤,而且只經過 `memory/store.py`。任何「什麼可以被寫」的保證都住在那個唯一的寫入者裡,永不住在產生那筆紀錄的模組裡 | `memory/store.py:1`;原則寫在 `:265-267` | `tests/test_store.py`(它引用 T-A1..T-A4)、`tests/test_erase.py`。理由原始碼裡就寫著:*「一個在讀取端強制的保證只是一句註解;在唯一的寫入者裡強制,它對從來沒聽過 profile 模組的代碼也成立」* —— 九個節點裡任何一個都能直接碰到 store,所以一個「自己不去呼叫寫入 API」的生產者只約束得到走它的呼叫者 |

### D1 —— 唯一一個帶已知缺陷的不變量,寫出來而不是抹平

I2 有**同一套詞彙的兩份實作,而活著的那一份不產生 finding。**
`safety/guard.py:318 gesture_findings()` 把回覆裡的標籤拆成「接受的」加上**每一個被拒絕的標籤一條 finding**,
而 `:331 spoken_text()` 回傳剝掉標籤後的回覆。**兩個都沒有呼叫者。**
`agent/agent_node.py:264-269` 用 inline regex 把兩者都重新實作了一遍,而且**沒有做白名單檢查** ——
每一個 `\w+` 的匹配都被發到 `/body/gesture`。

**要精確講清楚什麼被攔住了、什麼沒有。** 沒有不安全的東西到得了致動器:
`body/body_node.py:123` 做 `GESTURES.get(name)`,不認識的標籤就被丟掉;
而那個 containment 是**被宣告的**,不是意外 —— `agent/tools.py` 的 `EGRESS[GESTURE]` 那一列記著
`enforcement=ENFORCED`、`enforcer="body.gestures.GESTURES"`,還有一句寫下來的理由,
而 T-D3 守著白名單的唯一創造者。**所以安全性質是成立的。**

真正丟掉的是**稽核軌跡**。那個為此而寫的函式會把被拒絕的標籤變成一條 finding;
活著的那條路徑把它變成**沉默**。今天沒有任何地方記下「模型要了一個這台機器人沒有的手勢」,
而那恰恰是會告訴你「模型正在漂離白名單」的訊號。
**強制往下游搬了一跳,而可觀測性在路上被丟掉了。**

它被記成 `infra/dormant_seams.tsv` 的兩列 `defect`,每一列都指名 R1.6 是修它的階段,
而 `tests/test_wiring_census.py` 把那兩列釘在真正的那幾個 regex 與那個 `.get(name)` 上,
所以這個重複沒辦法只在一個方向上被靜默解決。
它寫在這裡而不是只寫在 commit 訊息裡,因為**一個只有閘知道的缺陷,是下一個讀者會重新發現一遍的缺陷。**

### 每一條出口,以及真正在上面強制的是什麼

`agent/tools.py:394 EGRESS` 存在的理由是:**語音不是唯一的出口,而今天它是唯一有人想到要守的。**
它列出模型的輸出到得了的每一條通道,連同**事實上**跑在上面的強制者。
讓這張表值得存在的是最後一欄:它區分 `NOT_WIRED`(強制者在這個 repo 裡,而沒有東西呼叫它)
與 `NO_ENFORCER_TODAY`(根本沒有東西可以呼叫)。
這兩者是同一種缺席,而修復成本差很多;把它們折在一起,就會讓這份文件把 S7 描述成「保護」。

| 通道 | 承載什麼 | 模型到得了嗎 | 今天的強制 |
|---|---|---|---|
| `SAY` | 機器人說出口的話 | 是 | **`NOT_WIRED`** —— `safety/output_guard.py` 存在,而一次 AST 普查在生產檔案裡找到**零個**呼叫者。這條通道**事實上沒有守衛**,而這一列自己的測試會在 R1.6 落地時變紅 |
| `GESTURE` | 全身動作 | 是 | `ENFORCED`,由 `body.gestures.GESTURES`(它在稽核上的代價見 D1) |
| `GAME_CMD` | 對局狀態轉移 | 是 | `ENFORCED` —— `game_node` 自己擁有 cooldown 與停止反射,所以模型發的 `[game:start]` 是一個**請求**,反射層可以拒絕 |
| `SKILL_TOOL_CALL` | `skills/` 底下的一次檔案讀取 | 是 | `ENFORCED` —— containment 檢查在**解析過 symlink 之後**的路徑上做,而拒絕是以 `REFUSED` 回來,不是以錯誤回來(T-I3) |
| `INTERRUPT` | 讓機器人閉嘴 | **否** | `NO_ENFORCER_TODAY`,而這是對的:它由 `on_asr` 在搶話時發出,永不來自模型文字;它不承載內容,最壞情況是沉默,而沉默是安全的那一端 |
| `MCP_TOOL_CALL` | 遠端 MCP 伺服器做的任何事 | **否** | `NO_ENFORCER_TODAY` —— 沒有 MCP client,`REGISTRY` 也沒宣告遠端工具。`invoke()` **會讀這一列**,所以宣告第一個遠端工具的那一天,它會一直被拒絕直到有東西被寫進這裡 |

最後那一列是值得抄的樣板:**閘與普查是同一個物件,所以它們沒辦法漂開。**
另外注意 `SAY` 的形狀有多誠實 —— 整個系統裡**最重要的那條通道**,
就是那條「強制者躺在 repo 裡而沒有東西呼叫它」的通道。R1.6 就是那一列。

**這一切背後有一個詞彙決定。** `invoke()` 回傳**六種**結果之一,而其中**恰好一種**代表邊界動作了。
`REFUSED` 是一個關於政策的主張;`UNREACHABLE` 是一個關於網路的主張。
一份把後者算成前者的報告,說的是「這台機器人被一次斷線保護了」。

## 4. 刻意不蓋的東西,以及它處於三種狀態的哪一種

一份對三種完全不同的認識狀況都寫「我們不做 X」的文件,比什麼都不寫更糟,
因為它告訴下一個讀者證據已經蓋棺。這三種狀態在這裡被分開,而先前內部的措辭凡是把它們塌在一起的,都在這裡更正。

### 4.1 被量測證偽

| 不做 | 為什麼,帶數字 |
|---|---|
| **小模型當路由器 / 升級判斷者** | 第七輪 §1:路由高原是 **+2.13 pp**,而那要付 10× 資料、3× encoder 加微調 —— 而且那個數字是**對標籤 oracle 的上界**。熵路由器在 TextWorld 上的升級率是 **0.0%**。在 10% 風險預算下,**零個**模型配對可被認證。HybridLLM 在 21 個方法中**最差**;R2V 在 3/3 設定上嚴格劣於純 LLM |
| **在這個 agent 裡的任何地方加強化學習** | 第七輪:RL 可被接受的位置**恰好是獎勵由非 LLM 感測器量出來的地方**,而這個條件排除掉這個系統擁有的每一個介入點。用「參與度」當獎勵比沒用更糟 —— 它直接朝著「不要講真話」優化。另外還有一個更前面的、結構性的理由:**這台機器人根本不跑物理。** `body/body_node.py:98,146` 呼叫 `mujoco.mj_forward`,從不呼叫 `mj_step` —— 關節位置是直接設定的,所以它不會跌倒、不會失衡、沒有接觸力。**一個不產生後果的環境,沒有東西可以被獎勵** |
| **在 T4 上訓練運動 policy** | 第六輪:即使訓得出來,沒有 system identification 也遷移不好 —— 仿真裡的 `armature = 0` 意味著在仿真裡調好的增益不會帶到真機。部署別人預訓練的 `motion.pt` 是**用** RL,不是**做** RL,而且成本差大約三個數量級。而且要注意先要付什麼:從 `mj_forward` 走到 `mj_step` 是一個**沒有被定價的前置條件**,不是一個開關 |
| **salience 公式裡的韻律情緒** | 第五輪:從生物訊號推斷情緒在 EU AI Act 下是高風險。`memory/salience.py` 因此丟掉語音韻律訊號,而 T-C6 斷言兩側 —— 功能關掉,以及一個把它打開的正控 |
| **拿 Ebbinghaus 式衰減當遺忘權機制** | 一條衰減曲線不是刪除。抹除必須是一個**帶收據**的動作(墓碑、串聯、確認),而那正是 `memory/erase.py` 與 T-C4 實作的東西 |
| **模型當測試的判官** | 上面的 I6 |

## 5. 測試在哪裡,對照風險在哪裡

這是 §1 之後第二大的誠實缺口,而它寫在這裡是因為**一個測試數量不是一個安全論證**。

R0–R4 一件都不需要它們。寫清楚每一件擋住什麼是重點:**一個沒有具名後果的阻塞會變成永久的藉口。**

## 7. 這個檔案怎麼被防止腐爛

四個機制,從這個 PR 起四個全部生效:

1. **[`docs/INDEX.md`](INDEX.md) 加 `infra/doc_status.tsv`** 給 `docs/` 底下每一份文件一個**封閉集**裡的狀態,
   在適用時再加一個具名的後繼者 —— 包含**「部分被推翻」**這一形,因為 §4.4 的情況
   (量測站得住,引用站不住)跟「被取代」不是同一件事,而一個只有兩個值的欄位會把它壓平。
   第四輪就是那個「關係欄必須用 `;` 串接而不能只放一個值」的理由:它有**兩個**互相獨立的推翻者,
   只給一格會逼人丟掉其中一個,而那一列讀起來仍然像是完整的。
   新文件不能靜默加入,陳舊的列本身是 finding,而 `infra/doc_status.py` 把索引、表與目錄
   **三個方向**都對帳。它同時讀這個檔案 §0 的那句歸屬:先前一版把「推翻第四輪」記給第七輪,
   而第七輪除了**贊同地引用**之外從沒提到第四輪 ——
   關於「哪份文件推翻哪一份」的散文,跟任何其他散文一樣沒有被驗證過。
2. **§1 的休眠主張是跟樹兩個方向對帳的**,由 `infra/wiring_census.py` 做,
   所以一個「接了子系統卻沒刪掉它那一列」的 R1 PR 會紅。
   **而這個檔案裡的數字現在也被閘住了 —— 這一節第一次寫下來的時候還沒有。**
   `infra/doc_counts.py` 把案例數、突變體數、模組數拿去跟 `pytest --collect-only` 對帳,
   而它的 `DOCS` 原本是 `docs/test-design.md`、`README.md`、`README.zh-TW.md` ——
   所以上面 I8 引用的那個收集案例數(62)是手查的,而它就坐在一份「整篇都在論證手查的數字會腐爛」的文件裡。
   R0b-2 把那個 tuple 擴到這個檔案、它的中文版、`docs/plan.md`,
   以及 `pytest.ini` —— 最後那個根本不是文件。`mutation` marker 的說明文字帶著
   整層的秒數,好讓它們不會跟它們所描述的那個 marker 脫節,而它們已經舊了兩輪:
   一段解釋「為什麼每一輪都要重新量一次時間」的散文,引用的是一個 1512 個案例、
   304 個突變體的套件。所以那個 tuple 的成員資格是**「引用了這些數字的檔案」**,
   永遠不是**「`docs/` 底下的檔案」**。
   這次擴大另外有兩個細節值得留著,因為兩個都是先犯了錯才學到的:
   加一條路徑只讓一個檔案**可讀**,在有一個 pattern 從它裡面引出一個數字之前什麼都沒被檢查 ——
   所以每一個突變體都是「改文件裡的數字」,永不是「把 tuple 縮小」。
   還有 I8 那句話引用的是**兩個**量 —— 案例數與測試函式數 —— 那需要兩條各自的導出;
   用一條導出去查兩個數,會讓它們之間的落差可以自由漂移。

   這次擴大也找出了檢查**太窄**、而不是不存在的地方。`docs/test-design.md` §0 每一列
   說了兩個數字 —— 這個檔案收集幾個案例、其中 L3 選到幾個 —— 而只有前者曾經被讀過。
   把後者也對帳,第一次執行就抓到三列是錯的:一列寫 13 而那一層收集到 12,
   另外兩列只寫了具名突變體的分解(17 + 1、8 + 2)、**完全沒有總數**,
   所以收集數沒有任何數字可以跟它不一致。**一個分解不是一個總數**:
   17 + 1 只對會自己加起來的讀者才是 18,而閘不會加法。散文也是同一個三行結構:
   一個模組的案例數同時寫在表格裡與討論它的段落裡,而表格檢查只讀表格 ——
   那正是當初 25-vs-23 那一對相隔四行還能活下來的方式。這些散文位置現在是**掃**文件的句型
   掃出來的,不是列出來的,所以下個月新寫的段落在寫下的那一天就被檢查;
   掃到零處是 finding,因為零代表句型被改寫了。
3. **§4 裡每一個「不做」都保留它的狀態標籤。** 當證據到來、把一項從 §4.1 / §4.2 / §4.3
   之間搬動時,**那個搬動就是那次修改** —— 不是一次會抹掉「它原本是哪一種狀態」的改寫。
4. **導出沒有自動化的數字要帶它的日期與它的分母。** §1 的 25.3%、§5 的行數、§2 的延遲數字,
   每一個都寫明它是對什麼量的、什麼時候量的,因為另一種形式 ——
   一個沒有分母的百分比 —— 正是一個過期數字活得最久的形式。
   這個檔案凡是更正了先前的主張(§1 的 26.6%、接著是它的 25.8%、§5 的「932 行」、
   §6 的 Guardrails 那一列),更正都寫出舊的數字是什麼。§1 那個百分比兩輪之內被更正了兩次,
   而這正是「請引用接縫數而不是這個百分比」的理由:接縫動了那個數才會動,
   而任何人在任何地方加一條測試,這個百分比就會動。**一個把它取代掉的東西藏起來的更正,是在要求下一個讀者相信它**,
   而這個檔案的整個論證就是:信任不是機制。
   一個計時數字還要帶兩樣東西 —— 它的 **n** 與機器的**負載** ——
   因為一個窄的區間不是穩定性的證據:這一輪整套測試最早兩趟讀到 239.4 s 與 239.4 s,
   到小數第一位都一樣,而同一條指令在同一棵樹上再跑六趟,跨度是 **137 s**。
   那個寬度接著殺掉了兩趟版本已經寫下的三個結論(有負載時比較慢、部分之和小於全體、
   這一輪比上一輪慢),所以 [`docs/test-design.md`](test-design.md) §3
   現在在每一個區間旁邊寫上 n,並且寫下它在第幾趟停止加量。
