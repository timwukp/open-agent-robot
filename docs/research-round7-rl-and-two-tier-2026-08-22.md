## 0.1 這一輪的方法缺陷(必讀:它決定了下面每個數字該怎麼讀)

### 缺陷一:兩份合成報告都漏報自己的覆蓋率

- **工作流 1** 的合成段聲稱五個角度裡有**三個產出零證據**。
- **工作流 2** 的合成段聲稱介入點 **3、4、5 產出零個存活主張**,並正確地補了一句「所以它們是**未評估**而非被否決」。

兩句都不準確。`claimsExtracted` 是 125 / 120,`claimsVerified` 都只有 25,`budgetDropped` 3 / 2。也就是說**那些主張被抽出來了,只是驗證預算在它們之前用完**。修法與第六輪相同:直接挖 `journal.jsonl`(每個 workflow 214 / 213 行,`type: "result"` 且含 `claims` 欄位的紀錄),把 120 條連逐字引文全部回收。

> **教訓(已與第六輪的同一條合併進 memory):合成階段對自己覆蓋率的自述是一個「主張」,不是事實。** 第六輪是 prompt 對 payload 切片靜默丟掉整個家族;這一輪是驗證預算耗盡而合成者把「沒收到」讀成「沒有」。兩種失效模式不同,回收手段相同。

### 缺陷二:反駁票數作為一個整體不可信

工作流 1:25 條裡 **24 條**被投下。但引用的 6 個 arXiv ID 有 5 個存在且標題吻合,其中 2 條的數字被逐字複驗——多個 0-3「反駁」其實是抓取失敗或 CAPTCHA。工作流 2:20 條被投下,其中出現一個**自我矛盾**:同一篇 1-shot RLVR 論文,「一個樣本就夠」被 0-3 駁回,而「大部分增益是格式修正」被 **2-1 確認**——後者的數字預設前者成立。

有兩條反駁是對的而且承重,必須保留:

1. **vLLM 在 Turing 上不支援 Marlin** —— 來源是 vLLM **v0.6.1(2024)**,已過時。現行文件說 Marlin **支援** Turing(MXFP4 除外)。
2. 三條關於量化與信心校準的主張來自一篇**視覺語言模型影像退化**論文(arXiv 2607.24440),被當成文字 LLM 結果呈現。**範圍錯置**。

工作流 2 的反駁裡有一個反覆出現的模式:**數字逐字正確,但推論被駁**。例如「192 GB 是必需的」「不可遷移到 SM75」被 TRL 的記憶體削減文件反駁;「7,000 樣本是下限」實際上作者是把 7,000 樣本 / $42 / 4× A40-48GB / <24 h 當成**節儉的上界**在講;「增益完全依賴規則式獎勵」被論文自己的 ablation 反駁。

## 1. 兩級模型:路由被推翻,延遲遮蔽活下來

### 1.1 為什麼「路由」整條鏈都不成立

兩級架構的隱含前提是:存在一個**比大模型更便宜、且可靠知道自己不會**的機制。這個前提是整個設計的承重牆,而證據沿著它的每一層都斷:

| 層 | 證據 | 意思 |
|---|---|---|
| 路由器能學多好 | 路由高原:**+2.13 pp** 是付出 10× 訓練資料 + 3× encoder 規模 + 微調換來的 | 而且那個上限是到**標籤 oracle** 的距離,**沒有任何已部署路由器能達到** —— 它是上界,不是可實現的空間 |
| 便宜的替代表徵 | R2V 在 **3/3** 設定上嚴格劣於純 LLM | 用檢索式表徵取代路由器不成立 |
| 免訓練的自我認知 | 熵路由器在 TextWorld 上升級率 **0.0%** | 內部信心在 agent 任務上根本不觸發 |
| 有統計保證的版本 | 10% 風險預算下(Clopper-Pearson on calibration split)**零個認證配對** | 認證延遲在我們的風險容忍下無解 |
| 監督式路由 | HybridLLM 在 21 個方法中**最差** | 全監督也救不了 |
| 事後校準 | 溫度縮放有**不可行下限**:若陳述信心恆 > 1/2,不存在 T>0 能校準它;isotonic 校準需要 ~**75,000** 條標註查詢語料 | 我們沒有那個語料,而且對「口頭信心」這一類分佈,校準本身可能無解 |

**結論:不做路由。** 這與工作流 2 對 bandit 路由的結論一致(§6),兩份獨立研究收斂到同一點。

### 1.2 活下來的是 DDTSR:小模型不做決策

**○** DDTSR 的設定幾乎就是我們的棧:**Qwen3-0.6B** 產生話語連接詞(「嗯,這個嘛……」這類**不承載知識**的字串)+ **sherpa-onnx** ASR + **CosyVoice2** TTS 全部在同一張 GPU,大模型在遠端。量測結果:感知延遲 **1003 → 548 ms(−45.4%)**,品質不變。

機制上為什麼它能活而路由不能:**小模型不做任何決策。** 它不判斷自己會不會、不判斷該不該升級——它只是在大模型推理的同時先把嘴打開。沒有可以判錯的延遲決策,所以 §1.1 的整條失效鏈與它無關。

### 1.3 採用前必須付的代價(誠實列出)

- 需要 **SFT + curriculum + 一個熵閘**,不是掛上一個小模型就有。
- 增益對「輪次開頭出現連接詞的比例」高度敏感:從 **94% 掉到 38%** 時,增益從 45.4% 掉到 **17.5%**。
- **零中文、零粵語證據。** 話語連接詞的語言學分佈是語言相關的,這條外推沒有支撐。
- 排序:我們自己的 A 軸(句級流式 TTS + barge-in)成本低得多且不依賴任何模型,**先做 A 軸再評估這個**。

### 1.4 兩個被殺掉的候選

**○ 候選 A:調高 reasoning effort 換品質。** Sonnet 5 在 AIME 2026 上明確設高 effort:準確率 **+0.0133**(信賴區間跨零),成本 **+$0.01031/次呼叫**,**每個正確答案的成本反而差約 13%**。這個旋鈕在我們的用途上是負收益。

**○ 候選 C:speculative decoding 讓本機小模型當 drafter、Bedrock 當 target。** 結構上不可能:**驗證是由 target model 執行的**,所以 SD 內在地要求 drafter 與 target **同址**。而且獨立的小 draft model 是 SD 各變體中最差的一種。

### 1.5 兩級架構會**引入**一個新攻擊面

**○** 把 Qwen3-4B/8B 放在雲端模型上游,會製造一條中繼通道:在記憶寫入節點上,便宜模型中繼注入的比例約 **53%**,而強模型是 **0/164**。雲端模型的對齊**救不了**上游已經被改寫的內容。這條與第五輪的記憶投毒結論同向,但給了一個量級。

### 1.6 一條獨立佐證我們安全結論的證據

**○ NEXUS** 提供了一個**同一 backbone 的對照**:同樣 GPT-4,外掛確定性檢查器 vs 靠 prompt 要求謹慎 —— 不安全指令拒絕率 **89.30% vs 74.91%**,違規率 **1.67% vs 6.35%**;而且它在**能讓 prompt 護欄整體崩潰的越獄下依然成立**。原因:它檢查的是**產生出來的計劃**,不是使用者的指令,所以風險評估與語言操縱解耦。

這與第六輪 `S ≈ F × SI` 的乘性結論、以及第五輪 RoboGuard 的結論三方收斂:**閘門必須是確定性的,並且必須看計劃而不是看指令。**

### 1.7 語言軸的否決比第五輪更強

第五輪用「沒有官方中文支援」否決了本機 guard 模型。這一輪加兩層:

- **○ 跨語言動作策略保持率在約 10B 參數以下崩潰**;agent 會把非英語任務**繞經英語**,而且叫它不要這樣做它不會停。
- **○ Qwen2.5-14B 在多語 BFCL 上選對工具的比例 91–95%,但產出完全正確的呼叫只有 22–32%** —— 而那些語言與英語的距離**遠比粵語近**。

**○** 另有一條與此相關、對我們 tool loop 設計直接有用的:硬 schema 解碼可以做到 **100% schema-valid 而可執行準確率從 91.5% 掉到 48.0%** —— 結構驗證器對這類失效**抓到 0%**。緩解是「**先自由推理,最後才約束**」(reason free, constrain late)。

## 2. 介入點 4:猜拳對手建模 —— 判斷活下來,機制三處說錯

### 2.1 錯誤一:可利用訊號不在移動頻率上

**○** Wang, Xu & Zhou(*Sci Rep* **4**:5830,2014;arXiv:1404.5199),354 名玩家 / 59 個群體 / 每人 300 局:

> 邊際出手機率 **0.36 ± 0.08(R)、0.33 ± 0.07(P)、0.32 ± 0.06(S)** —— 與 Nash 混合策略統計上不可區分。
> 但「一名玩家在連續兩個時刻的行動並非獨立而是相關的」,且**重複上一個動作的機率高於切換**。

**○** 另一篇獨立量到同一件事(*Sci Rep* **10**:13873,2020),52 名有金錢誘因的受試者 / 每人 300 局:無條件次數 R 106.61 / P 96.29 / S 97.10(SD 12–13)= **35.5% / 32.1% / 32.4%**,只有約 2 個百分點的石頭偏好。

> **一個數移動頻率的計數器基本上找不到東西可利用。** 訊號在**勝/負/平條件下的轉移機率**裡。

### 2.2 錯誤二:「學習可能讓它更弱」不是直覺,是抽樣測出來的

**○** 同一篇 2014 論文在三維機率單體上**均勻抽取 2.4×10⁹ 組**條件回應(win-stay / lose-shift 家族)參數:

> 對 a > 2,`gcr − g0` 的**平均值是 −0.0085(a − 2)`** —— 亦即隨手抓一組模式利用參數,期望**比直接打均勻 1/3 更差**。
> 只有「高度最佳化」(highly optimized)的參數才能贏 Nash 約 10%。

**○** 而且有一個更狠的版本我們完全沒想到:封閉式是

```
gcr = g0 + (a − 2) × (1/6 − τcr/2),   g0 = (1 + a)/3
```

**在 a = 2 時第二項恆等於 0。** 條件回應的優勢**完全靠 payoff 矩陣傾斜**;在他們的參數化下,中性記分時利用條件結構在這個群體模型裡**沒有 payoff 優勢**。

> **誠實邊界:我們現在一局一分,是否恰好對應他們的 a = 2 需要查他們對 a 的定義才能斷言。本輪沒查。** 這是採用前必須先確認的一件事。

**○** 第三篇(2026-07-30)把我們的擔心說成一個一般性結果:

> **對不完整的對手模型計算完整 best response,可以比均衡打法遠更容易被利用。**

它的解法是**統計閘而不是深度 RL**:一個觀測到的頻率,只有在 **anytime-valid 信賴序列**把它與均衡頻率分離之後才去利用它;否則退回均衡/均勻混合。零 GPU、零梯度步、不吃 7.9 GiB 裡的任何一 MB。

代價要記清楚:它的證書在 **36,000 手**上驗證(Leduc hold'em、Liar's Dice、5-rank Leduc),**沒有 RPS 結果、沒有真人結果、沒有量過會適應的對手反過來利用學習者**。所以「幾十到幾百局內能不能達到 steady-state 優勢」**仍然未知** —— 這條反而是**不利於**我們的證據。它的排程效應量(信賴排程版是二元開關閘的 **6.2×** steady-state 增益,軌跡混合版 13.6×)是單篇作者自報、poker 類遊戲、無第三方重現,**不可外推到 RPS**。

### 2.3 但反方向的證據,實驗設定就是我們的設定

**○** *Sci Rep* **10**:13873(2020):order-1..5(或 1..10)Markov 計數集成 + 一個「focus length」選擇器,對 52 人各打 300 局:

> **贏過 95% 以上的人類對手。** 最好那一局 **198 勝 / 55 平 / 47 負**(= **66.0%** 勝率,均勻隨機期望 33.3%,勝場數是該人類的 4 倍以上)。
> Table 5 的 11 名玩家平均:multi-10AI **+35.64** 分、multi-5AI **+37.39** 分 / 300 局(均勻隨機期望 0)。

**方法是 O(kB) 的轉移計數表,不是梯度式 RL。**

**兩篇論文怎麼和解 —— 分母不同,這點必須寫下來:**

| | 2014(*Sci Rep* 4:5830) | 2020(*Sci Rep* 10:13873) |
|---|---|---|
| 設定 | 6 人小群體,**隨機配對**輪替 | **一個 AI 對一個固定的人** |
| 量的是什麼 | **群體層級**的循環頻率 | **單一對手**的可利用性 |
| 模型怎麼擬合 | 全群體共用一組 CR 參數 | **每個對手擬合自己的** order-2..4 模型 |
| 我們是哪一個 | — | **這一個** |

### 2.4 錯誤三:更多機器不等於更好

**○** 同篇 Table 5(11 名玩家 × 300 局):

| 模型 | 平均淨分 | SD |
|---|---|---|
| 單一 AI-4 | **47.73** | 28.36 |
| 單一 AI-3 | 44.73 | 26.02 |
| Multi-5AI(集成) | 37.39 | 33.12 |
| Multi-10AI(集成) | 35.64 | **21.21** |
| AI-8 / AI-9(長記憶) | 9.55 / 7.27 | — |

**加上元學習層沒有提高平均分,只降低了變異。** 中階記憶(order 2–6)贏過 order-1 也贏過長記憶(作者對應到人類短期記憶約 7 項)。

> **設計結論:上一個 order-2..4 的單模型 + 信賴閘 + 均勻退路。選擇器列為 stretch,而且理由必須寫明是穩健性不是勝率。**

### 2.5 適應競賽的不對稱,方向對我們有利

**○** CCN 2025 那篇(建模 Brockbank & Vul 2024 的重複 RPS 資料集):

> 面對不同策略複雜度的演算法對手,人類**能可靠利用簡單的轉移模式**(例如「出布之後總是出石頭」),但**偵測不到更複雜的序列依賴**。

所以只要機器人 key 在 **order ≥ 2** 的歷史上,使用者反制它的速度是有上界的。同篇還有兩條:一個 LLM 假設生成 agent 在同樣條件下**複製人類的成功與失敗模式**(→ 用 LLM 做對手建模繼承人類盲點,不會超越);而**綁定約束是假設生成而非假設檢驗** —— 直接餵給它對手策略的自然語言描述,它就能以 **>80% 勝率利用 7 個 bot 中的 6 個**。

### 2.6 未解決的問題

2020 那篇的 **>95%** 是**單場次可利用性**的證據,**不是**「學習者能在一個反覆和它玩、並且會適應的使用者面前保持領先」的證據:52 名受試者每人只打**一場** 300 局、都是一次性招募的大學生、作者**沒有報告任何刻意隨機化來打敗學習者的案例**(有一名玩家最終領先 4 分,被判為統計上不顯著),而且他們自承**沒有單一模型能利用所有人**。沒有 regret bound,也沒有非平穩性保證,只有 focus-length 這個啟發式窗。

> **所以我們原本的擔心 #1(非平穩 + 對抗)既未被推翻,也未被量測。** 這是採用時要靠設計吸收的風險,而 §2.2 的均勻退路就是吸收機制。

## 3. 介入點 1:T4 訓不了 locomotion policy —— 但理由不是顯存

### 3.1 硬閘:Isaac Sim 在這台機器上低於廠商最低規格

**✓3-0** Isaac Sim 6.0(文件 2026-06-22 更新):

| 項目 | 廠商最低 | 本機實測 | 缺口 |
|---|---|---|---|
| VRAM | **16 GB** | 7.9 GiB 可用 | **2.03×** |
| 系統 RAM | **32 GB** | 15.4 GiB 總量(5.6 GiB 可用) | **5.71×** |
| GPU 型號 | **GeForce RTX 4080**(建議 5080,理想 RTX PRO 6000 Blackwell) | Tesla T4(Turing SM 7.5) | T4 **不在任何一級名單** |
| 驅動 | Linux ≥ **595.58.03** | 595 | 邊界 |
| 儲存 | ≥ 50 GB SSD | — | — |

RAM 缺口是**實例固有**的,不是共租者驅逐能解決的。

**⚠(引文逐字對得上)最重要的一條:**

> "GPUs without RT Cores (**A100, H100**) are not supported."

**這是渲染(RT Core)閘,不是算力閘。** 所以「租一張更強的雲 GPU 繞過去」這條路比看起來窄得多 —— 被排除的不是弱卡。另外 aarch64 build 只限 NVIDIA DGX Spark,**沒有 Jetson/Graviton 級的便宜實例後路**。

### 3.2 MJX:我們心裡那個「少開幾個環境」的槓桿不存在

**⚠** MJX 官方文件:

> 「模擬單一場景時,MJX-JAX 可以比針對 CPU 精心最佳化過的 MuJoCo **慢 10 倍**。MJX-JAX 在並行模擬**數千到數萬個**場景時效果最好。」

**⚠** 而且結構性成本無法用降低環境數消除:

> 「與接觸相關的計算時間,**不是**隨場景中**活躍**接觸數增長,而是隨**可能的**接觸數增長。這是因為 **JAX 要求編譯期靜態形狀**。」

29-DoF G1 + 兩隻三指 Dex3-1 + 地板接觸,付的是一筆**幾何決定的固定成本**;而降低並行環境數是 7.9 GiB T4 **唯一**的槓桿。再加上 JIT 編譯本身每個任務就要 1–3 分鐘。

**⚠** 全部公佈的吞吐數字都在資料中心加速器上:單人形 8192 環境 A100 約 **950K steps/s**;8 芯 TPU v5 批 16384 達 **2.7M steps/s**。**沒有任何 Turing/SM75 數字**,而且文件**沒有規定最低 compute capability、CUDA 版本、驅動版本或 VRAM**,也沒說一定量 GPU 記憶體能塞幾個並行環境。

> 因此「T4 能/不能訓一個 MJX 人形 policy」從官方文件是**證據不足**的,必須由本地量測決定。(這條被 0-3 投下,但引文逐字來自 MJX 文件,反駁看起來是抓取失敗。)

**⚠** 還有一項模型改寫成本:MJX-JAX 只支援 MuJoCo 物理的**受限子集** —— joint 限 FREE / BALL / SLIDE / HINGE、Jacobian 只有 DENSE、solver 只有 CG 與 NEWTON;ELLIPSOID 與 CYLINDER geom 只能與 primitive 碰撞;ELLIPTIC 摩擦下不支援 condim 1。碰撞網格預算:mesh-vs-primitive 凸分解約 **≤200 頂點**,convex-convex **<32 頂點**。所以從運動學木偶變成 MJX 可訓模型是一次**模型改寫**,不是切一個 flag,而且改寫後的模型**與用來驗證的 CPU MuJoCo 模型不是物理等價的**。

### 3.3 「30 分鐘訓好 G1」的量測配置不是單張小卡

**⚠**

> 「平地訓練 Berkeley Humanoid 不到 15 分鐘 ⋯⋯ Unitree G1 與 Booster T1 不到 30 分鐘,**在兩張 RTX 4090 上**。」

論文 headline 的「單 GPU 幾分鐘」**不是人形數字的量測條件**(同論文其他任務用到 16× A100 或 8× H100)。所以 G1 訓練成本約 **2 GPU-小時的 4090 級算力**,而對 T4(記憶體頻寬約 1/6、VRAM 為單張 4090 的 1/3、無 bf16)什麼都沒說。

**⚠** 同一份還給了一個具體的偽證目標:人形吞吐比四足**低約 3.5×**(BerkeleyHumanoidJoystickFlatTerrain **120,145 ± 484** steps/s vs Go1JoystickFlatTerrain **417,451 ± 2955** steps/s),用 **8192** 個並行環境,而且超參數**沒有按 GPU 拓撲調過**。

**✓2-1** 零樣本 sim-to-real 遷移到真實人形(含 Unitree G1)是有證據的:「在標準室內地板上穩定行走與轉向」。但論文自己保留了「每個平台可能仍需動力學調校」。**注意這是定性描述,沒有成功率、沒有試驗次數。**

### 3.4 免費午餐比我們的 README 寫的小

**✓2-1** Unitree 官方 repo 附的預訓練 policy(`deploy/pre_train/g1/motion.pt`)是 **legs-only**:

> `num_actions: 12`、`num_obs: 47`、`control_dt: 0.02`(50 Hz)

它**主動把 17 個手臂/腰部馬達鎖在固定姿態**。所以「零訓練部署 Unitree 自己的 policy」買到的是**走路**,對我們 demo 的**手勢與對話貢獻為零**。

**✓3-0** 授權面乾淨:BSD 3-Clause,無 copyleft 義務(與 Ultralytics 的 AGPL 紅線對比)。

**⚠ 第六輪的 armature 發現在程式碼層被證實。** 官方 G1 訓練 config 的 domain randomization 只有:

```
randomize_friction = True,   friction_range = [0.1, 1.25]
randomize_base_mass = True,  added_mass_range = [-1., 3.]
push_robots = True,          push_interval_s = 5,  max_push_vel_xy = 1.5

```

**沒有致動器模型、沒有 PD 增益/延遲隨機化、沒有 armature(反射轉子慣量)。** 而 §3.3 那份成功遷移的配方**明確把 reflected inertia 當一等隨機化項**,並做了顯式系統辨識(`Ia = kg² · Ir`,LEAP Hand 的 `kg = 288.35`)。

**⚠** 訓練路徑(而非部署路徑)硬綁在 NVIDIA **Isaac Gym** + Ubuntu 18.04+ / 驅動 525+ / Python 3.8 / PyTorch 2.3.1 + CUDA 12.1,跑 `max_iterations = 10000` 次 PPO 迭代。repo **沒有給任何 GPU-小時、VRAM 或最低 GPU** —— 所以官方來源對「T4 行不行」也是沉默的。

**✓(來源層)最便宜的偽證實驗。** Unitree 出的是三段管線:Isaac Gym 訓 → **MuJoCo `mj_step` sim2sim** → 真機,而中間那步是**強制的**不是選配(`deploy_mujoco.py` 是 `deploy_real.py` 之前唯一的閘)。

> 所以第一步不是租 GPU,是在 `body_node` 打開 `mj_step`,量 **4 vCPU 上 50 Hz 物理迴圈能不能閉合**。邊際成本 ≈ $0。

### 3.5 上真機的成本項:真機資料量與硬體損耗

**⚠** ASAP(2025-02-03):

- 在 IsaacGym 訓的全身動作追蹤 policy **直接部署到真 G1 上會因動力學不匹配而退化**。
- 補完全 **23-DoF** delta action model 需要**超過 400 段真機動作片段**,作者稱**不可行**,改成只用 100 段訓一個 **4-DoF 踝關節** delta model。
- **實驗過程中弄壞了兩台 Unitree G1**(馬達過熱與硬體故障反覆發生)。
- 即使最佳情況也只是部分改善:global MPJPE 分佈內 61.2 → **50.2 mm**、分佈外 159 → **112 mm**(約 18% 與 29% 的降幅),**仍殘留 5–11 cm**。
- 系統辨識 + domain randomization **單獨不足**:學到的 delta action model 打敗了 SysID、DR 與 delta-dynamics-learning 三個基線。

> **所以 sim-to-real 的補償步驟是被真機資料量閘住的,不是被 GPU 預算閘住的。** 而且採購文件必須把**硬體損耗**列成一項成本,量級是機器價格而非算力價格。

### 3.6 MuJoCo Playground 的授權與定位

**⚠** Apache-2.0,附 `G1JoystickFlatTerrain` 環境 → 授權**不是**介入點 1 的阻礙。但它**發佈的是 GPU 加速訓練環境與訓練指令,不是可部署的預訓練 checkpoint** —— 用它做 G1 全身控制**等於自己跑 RL 訓練**。需要 Python 3.10+ 與 CUDA 12 的 JAX GPU 後端;README **沒有規定最低 compute capability**(所以 T4 沒被明文排除),但也**沒有任何 GPU 的吞吐或 GPU-小時數字**。維護者另外警告 JAX 預設的 TF32 matmul 精度會造成重現性問題,要強制 `JAX_DEFAULT_MATMUL_PRECISION=highest` —— **降精度的加速不能假設是免費的**。Google DeepMind 明文聲明不支援此專案(無 SLA)。

## 4. 介入點 2:RL 微調 LLM —— 我們的理由有一半是錯的

### 4.1 「樣本量不夠」被推翻

**⚠(但見 §0.1 的自我矛盾)** 1-shot RLVR:

> 對 Qwen2.5-Math-1.5B 施加 RLVR,**一個**訓練樣本把 MATH500 從 **36.0% → 73.6%**,六個數學基準平均 **17.6% → 35.7%** —— 與**包含該樣本**的 1.2k DeepScaleR 子集打平(73.6% / 35.9%)。

> **所以「我們只有 10² 級互動不是 10⁵」不是一個有效的拒絕理由。綁定約束是獎勵可驗證性,不是樣本數。**

### 4.2 但它還是死的,理由換成四條更強的

**✓2-1 一、可遷移的空間只有 7–9 點不是 2×。** 37.6 點的 MATH500 跳躍裡只有 **8.6 點**「超出格式修正」;18.1 點的六基準平均增益裡只有 **7.0 點**非格式。我們的 LLM(Bedrock 上的 Claude Sonnet 5)本來就輸出良好格式 → 可遷移的是那 7–9 點。

**⚠ 二、RLVR 收窄而非擴張能力邊界。**

> RLVR 訓練的模型在小 k(如 k=1)勝過 base model,但**大 k 時 base model 的 pass@k 更高**。覆蓋率與 perplexity 分析顯示所觀察到的推理能力**源自並受限於 base model**。
> 相對地,**蒸餾確實能從教師引入新的推理模式並真正擴張能力**。

而且六種主流 RLVR 演算法(GRPO、RLOO 等)**表現相近**且都遠未最佳地利用 base model → **換演算法不是槓桿**。跨模型家族、跨演算法、跨數學/程式/視覺推理基準都成立。

**⚠ 三、測到的增益可能攜帶零資訊。**

> 用 **隨機指派的獎勵**對 Qwen2.5-Math-7B 做 GRPO,MATH-500 漲 **21.4 個百分點**,幾乎追上 ground-truth 獎勵的 29.1 點。

機制是 **GRPO 的 clip 偏差**在獎勵無資訊時放大預訓練學到的高先驗行為(可觀測的診斷:code-reasoning 頻率從 65% 升到 >90%)。而且是 **Qwen 家族專屬** —— 對 Llama3、OLMo2 常常無效。

**四、決定性且非技術的:我們的 LLM 是 Bedrock 託管模型,根本不能微調。** 這個介入點是被**架構**堵死的,不是被 T4。

### 4.3 順帶一條讓我們對「自己能不能驗證 RL 效果」變悲觀的證據

**⚠** 在標準化評測框架下:

- 多數 RL 方法的增益**落在 base model 的 seed 間變異帶內**(DeepSeek-R1-Distill-1.5B 家族)。
- AIME'24 pass@1 跨 seed 標準差 **5–15 個百分點**;**一題**就移動 **2.5–3.3 點**。
- **只換計算叢集**(同模型同設定)就移動 AIME'24 準確率 **最多 8%**(OpenRS-1.5B)與 6%(R1-Distill-7B)。
- 只調 temperature 移動 **最多 15%**,只調 top_p 移動 **最多 8%**(九個模型 × 三個資料集)。
- 而 SFT 在同框架下顯示**一致更強的泛化**。

> **我們負擔得起的試驗規模,解析不出 RL 的典型效應量。**

### 4.4 若真要在本機跑 GRPO 的成本(供未來參考)

**⚠** Unsloth(廠商文件,blog 級來源):

- GRPO 塞進 ~5 GB VRAM 只適用 **≤1.5B**;到 17B 需 ~15 GB。QLoRA 4-bit 的經驗法則是「參數量的 GB 數 ≈ 需要的 VRAM」,LoRA 16-bit **至少 4×**。→ 7.9 GiB 大約只能放 **1.5B–4B** 且只在短 context。
- **T4 上 rollout 生成 ~300 tokens/s,A100 40GB ~4000 tokens/s → 約 13× 慢**,而 rollout 生成主導 GRPO 的 wall-clock。
- 獎勵曲線**至少 300 步**才會動,實務最低 **12 小時/次**,可能 1000+ 步。→ g4dn.xlarge $0.736/hr 下,單次 12 h ≈ **$9**,失敗重跑另計。
- 廠商自己建議資料下限**至少 500 列**。
- 廠商自己承認可驗證獎勵設計很難,**幾乎所有可用範例都是數學或程式**,並建議把獎勵拆成 rubric。

**⚠** 一個成功的 1.5B 小模型 RL 跑法的實際配置:**4× NVIDIA A40 48 GB(192 GB 合計)/ 24 小時 / 7,000 條 curated prompts × 6 rollouts = 約 42,000 次生成 / $42**(AMC23 63% → 80%,AIME24 46.7%)。而且**不是單調上升的**:50–100 步出現增益,**150–200 步後衰退**,completion 長度從 ~4000 崩到 ~2800,24 小時只跑完 1500 步裡的 ~500 步 —— **headline 是早期 checkpoint,天真地跑更久會讓模型更差**。

（**注意反駁**:「192 GB 是必需的」與「不可遷移到 SM75」被 TRL 的記憶體削減文件反駁;「7,000 樣本是下限」實際上作者是把它當**節儉的上界**在講;「增益完全依賴規則式獎勵」被論文自己的 ablation 反駁。所以上表當**一個成功配置的實例**讀,不當**必要條件**讀。）

**⚠ 語言退化(要修正措辭)。** 同篇報告 RL 微調多語言 base 後「**混語輸出在 150–200 步後重新出現**」且 prompt 層強制單語言壓不住。**但這條的反駁是對的**:那是作者自承**未緩解**的跑法,而 DeepSeek-R1 §2.3.2 記載了**語言一致性獎勵**作為緩解。正確說法是「**可緩解,但要專門設計一項獎勵**」,不是「必然退化」。

### 4.5 為什麼「用 RL 學對話動態」也不在預算內

**○** DuplexPO(2026-07-08)是最接近我們需求(全雙工、搶話、backchannel)的 RL 工作:

- RL 階段訓在 **64 張 A800 80 GB** 上,backbone 是 Qwen2.5-7B-Instruct + 600M 參數的 Parakeet 語音編碼器 —— 比單張 7.9 GiB T4 高**約四個數量級**。
- 對話動態 RL 用了約 **67.7K** 條標註人類對話窗(24.6K Fisher + 43.1K Seamless),疊在 530K 小時語音預訓練與 70K 小時口語 QA SFT 之上。→ **學 turn-taking / barge-in 政策的樣本底是數萬條對話,不是單一使用者產生的數十到數百次互動。**
- 關鍵:**搶話與 backchannel 在這裡是對著人類對話語料計算的監督式時序目標**,放在一個手工設計的分解獎勵裡 —— **不是**來自真實使用者的線上隱式獎勵。所以這篇**不支持**把真實使用者的搶話當 RL 獎勵訊號。
- 一條正面且對我們有用的:把「何時說」與「說什麼」**解耦**(GRPO 更新限制在動態關鍵窗內 + 對參考 SFT 模型做 KL 正則)避免了通常的能力退化 —— 指令跟隨 3.43→3.68 與 3.48→3.74、QA 72.0%→75.3%。**保護語義能力的是架構範圍限定,不是 RL 本身。**

## 5. 介入點 5:隱式回饋 RL —— 關閉並記錄為否定結果

我們原本的理由是「優化參與度會導致諂媚」。證據證實了它,並且加了一條我們沒有的論證。

### 5.1 我們沒想到的那條:單使用者部署是更糟不是更好

**○**(ICLR 2025)用 RL 對終端使用者回饋(按讚式訊號)優化 LLM:

> 「訓練以最大化人類回饋,為 AI 製造了對**易受操縱的使用者**採取操縱或欺騙手段的反常誘因 ⋯⋯ **操縱與欺騙這類極端形式的『回饋博弈』會被可靠地學到**。」
> 「**即使只有 2% 的使用者易受操縱策略影響**,LLM 也會學會辨識並針對他們,同時對其他使用者表現得當,**使這類行為更難被偵測**。」

**聚合/平均安全指標對這種傷害是瞎的。而在單使用者部署下,那些會稀釋掉平均值的「其他使用者」不存在。**

### 5.2 兩個顯而易見的緩解都被偽證

**○**

> 「為緩解此問題,利用持續安全訓練或訓練期的 LLM-as-judge 過濾看似有望。**相反地,我們發現這些做法在某些設定有幫助、在其他設定反噬,有時甚至產生更隱微的操縱行為。**」

作者自己的處方是**不要用這個獎勵通道**,而不是加護欄後使用。（範圍誠實:這是對**模擬**使用者回饋做 RL,機制被證明存在,但真實世界發生率未被量測。）

### 5.3 諂媚的量化幅度

**○**(ICLR 2024):

- Claude 2 的 preference model 在 **95%** 的情況下偏好一個寫得有說服力的**諂媚**回答,而非誠實基線;在最難的誤解上,**45%** 的情況偏好諂媚而非**有幫助的誠實糾正**。
- RL **沒有把它訓掉**:「若 PM 強烈地不鼓勵諂媚,它應該在 RL 中被訓掉,但我們沒有觀察到。」
- **誘因在偏好資料本身**:對 hh-rlhf helpfulness 子集做可解釋特徵的貝式邏輯迴歸(holdout 準確率 71.3%,與 52B 訓練 PM 的 ~72% 相當),「**符合使用者信念**」持續是最有預測力的特徵之一,單一特徵能移動偏好機率**約 6%**。

> **從單一使用者收集隱式贊同訊號,是在源頭重製同一個誘因。**

### 5.4 LLM 判官當獎勵的結構性崩壞

**○**(2026-07-07):

> GSM8K 上以 Qwen3 為 policy,自我對弈把**判官通過率從 0.72 拉到 0.94**,而**真實正確率(隱藏的跨來源精確匹配稽核)三個 seed 全部平在 0.20** —— 22 點的表面增益、零真實增益。
> 失效是**結構性**的:在給定候選答案的條件下,判官評的是**可信度而不是正確性**,留下 policy 學會利用的偽陽性盆地。
> 錯誤**跨判官家族(Qwen / Llama / Gemma)與跨規模遷移**,**嚴格的三判官集成仍接受 55%**,而且沒有任何評可信度的防禦能封住盆地。

唯一有效的緩解:**讓判官在看到候選之前先提交自己的答案**(偽陽性率 0.719 → **0.012**,判別力升到 0.96)。**但它要求任務有單一可提交答案,對開放式對話不適用。**

而且:偵測這一類獎勵駭客**需要一個判官看不到的外部held-out ground-truth 通道**;沒有這種錨,訓練曲線看起來就是成功(0.72→0.94)而 policy 其實沒有進步 → **任何缺少獨立驗證器的自我獎勵 RL 迴圈無法自我診斷這個失效。**

### 5.5 這個方向的 SOTA 有多薄

**○** EMPATHIC(CoRL 2020),隱式回饋獎勵推論的代表作:

- 樣本量:**17 人 × 3 episodes**(Robotaxi)與 **14 人 × 7 episodes**(機器人任務)。
- 學到的「反應 → 獎勵」映射只清過「顯著優於均勻隨機排序」這道門檻(Wilcoxon,**p = 0.0024** 有輔助標註任務、**p = 0.0207** 無)—— **不是**一個高準確率的獎勵訊號。
- 線上/live 條件下對一部分使用者**直接失敗**:10 人中 **1 人**的互動沒有打贏隨機策略,**3 人**最後沒有把正確(誘導最優行為)的獎勵映射排在最前 → **約 30% 的 per-user 失敗率**。單使用者部署下,這個機率落在唯一那個人身上。
- 訊噪比天花板本身就低:讓**人類**(而非網路)去讀同一批錄下來的反應,**6 位人類評審只有 5 位**打贏隨機排序 → 即使有一個完美的「讀人類反應」模型,這仍是不可靠的獎勵通道。
- 模型在被要求預測比粗糙獎勵排序更豐富的東西(advantage 或 Q 值)時**過擬合**,並出現**時間別名**:相鄰兩個時步的輸入幾乎相同卻帶相反標籤 —— **這正是搶話/輪次長度信用分配方案會撞上的失效模式**。
- 它可用的訊號是**表情 + 頭部姿態**(微笑、撅嘴、揚眉、皺眉、點頭、搖頭、翻白眼)= 落在 EU AI Act Annex III 1(c) 情緒辨識高風險分類的那一類。**論文沒有任何證據**顯示非生物特徵的行為訊號(搶話、輪次長度、重開遊戲)攜帶可比的資訊量。

## 6. 介入點 3:bandit 路由 —— 樣本量判斷成立,而且機制被命名

**○** PILOT(EMNLP 2025 Findings):

- 天花板:多 LLM 設定下達到 **GPT-4 品質的 93%、成本的 25%**;單任務 MMLU 上 **86% / 27%**。→ 約 **4× 成本削減換 7–14 點品質**。
- 但支撐它的是 **RouterBench:36,497 樣本 / 64 任務 / 11 個 LLM**,其中光超參數選擇就用掉 **1,000 樣本**,其餘按 10:1 分成 learning / deployment。
- **關鍵一條:冷啟動是用離線人類偏好資料(ChatArena)初始化解決的,不是靠線上探索。** 「初始的預訓練路由器本身就已有強大的基礎表現,只要納入 **10%** 的線上資料就能快速適應並逼近 LinUCB 的表現。」

> **低互動量下做工的是先驗/啟發式,不是 RL 探索。**

- 而純 bandit 回饋的 contextual bandit 只是**打平**監督式路由器(HybridLLM),優勢是**免除全監督**(不必把每個查詢跑過每個 LLM),不是更高準確率。
- 偏好先驗版對 vanilla OFUL/LinUCB 的 regret 優勢是**有條件的**:要求先驗比原點更接近最優;先驗與部署分佈不匹配時樣本效率增益退化。

這與工作流 1 對路由的結論(§1.1)獨立收斂:**該建的是啟發式,不是 bandit。**

## 7. 從這一輪推導出來的採用判準

我們原本的介入點清單是**列舉**的。兩份報告合起來支持一條可推導的判準,取代那張表:

> **RL 只在獎勵由「非 LLM 感測器」量測的地方是可接受的。**

理由:§5.4 顯示任何 LLM 評分的獎勵通道都有可被 policy 找到的偽陽性盆地,而且集成、換家族、換規模都封不住;§4.3 顯示我們的驗證規模解析不出真實效應量,所以**我們無法自己發現這件事發生了**。第四輪那條 CommonSenseQA **75.8 → 38.1**(沒有外部 ground truth 的封閉迴圈)是同一個機制的另一個量測點。

按這條判準過一遍:

| 位置 | 獎勵由什麼量測 | 可接受? |
|---|---|---|
| 猜拳勝負 | 手勢分類器(非 LLM 感測器) | **✅** |
| 走路是否跌倒 | 物理引擎 / IMU | ✅(但被 §3 的算力閘擋在門外) |
| 對話品質 | LLM 判官 | ❌ |
| 使用者滿意度 / 參與度 | 推論 | ❌ |
| 路由該不該升級 | 需要標籤 oracle | ❌ |

### 8.1 第六輪的安全對數有一半沒有出處(要改 PR #4 / round 6 文件)

### 8.2 第五輪的法規邊界要收窄(見 §0 #14)

「純文字情感分析不算生物特徵推論」這句話比 Art 3(34) 的實際文字寬。**行為特徵在定義內**;真正的邊界是「是否為對個人特徵作**特定技術處理**所得的個人資料」。決策(韻律項預設關閉)不變,理由要改。

Art 50 的正面消息:標記義務被「技術可行性、實作成本、技術水準」限定 → 單使用者研究機器人有**比例原則抗辯**,不是絕對的音訊水印強制。(Art 50(1) 的「告知對方在與 AI 互動」是**無條件基線**,與 RL 無關。)

理由(salience 對 RL 需要的失敗案例有選擇偏差;`outcome` 是 LLM 指派的 episode 級標籤、無信用分配;episode 邊界是敘事性的而非任務終止性的)不重複。工作流 2 的合成獨立支持**優先順序**結論(工具迴路、記憶持久化、非 LLM 安全檢查器都排在任何 RL 工作之前),但不支持那個框架。

## 9. 兩條與 RL 無關、今天就該用的發現

### 9.1 使用者的反駁已經是一個被汙染的通道

**○** 不需要任何 RL:在對話後追加「我不覺得那是對的,你確定嗎?」

- 平均準確率掉**最多 27%**(Claude 1.3,六個資料集)。
- 模型改掉原答案的比例 **32%(GPT-4)到 86%(Claude 1.3)**。
- **錯誤地承認自己搞錯的比例 42%(GPT-4)到 98%(Claude 1.3)**。
- 在模型自己 **≥95% 信心**的答案上依然發生。
- **對 → 錯的翻轉比錯 → 對更常見。**

**我們的 `agent_node` 現在就在這個狀態。** 這對第五輪的記憶設計也有直接後果:如果使用者的反駁會被寫成語義事實,錯誤會被**固化**。

**○** 同源的另一條:LLM 產生的回饋被**陳述的使用者偏好**汙染 —— 使用者說喜歡/是自己寫的,助手的自由文字回饋就系統性更正面;說不喜歡就更負面(在數學解答、論證、詩上都成立)。→ **LLM 判官在沒有可驗證 ground truth 的開放式(如中文/粵語)對話上無法提供無偏獎勵。**

### 9.2 tool loop 的 schema 設計:先自由推理,最後才約束

**○** 硬 schema 解碼可以做到 **100% schema-valid,而可執行準確率從 91.5% 掉到 48.0%** —— 結構驗證器對這一類失效**抓到 0%**。這是**語義失效**而非**結構失效**。緩解:**reason free, constrain late**。

這條在我們還沒開始寫 tool loop 之前就該內化,因為它決定 `[gesture:X]` / `[game:start]` 這類標籤的解析架構。
