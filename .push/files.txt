# R0b-1 — 把「當前設計是什麼」從一台筆電的 ~/.claude/plans/ 搬進這棵樹,
# 並且在搬的過程中重新導出每一個數字。
#
# 這一輪一行代碼都沒動,加的是三份文件加兩份 README 的入口改寫。它值得寫,
# 是因為量到一個治理缺口:在這之前「設計是什麼」的答案住在 repo 外面,而 repo 裡
# 六份研究文件(169 KB)+ 一份審視(22 KB)裡有**四份完全沒有任何「已被取代」標記** ——
# 其中一份是第四輪,正是第七輪部分推翻的那一份。一個外部貢獻者要回答「現在的設計是
# 什麼」,得讀 191 KB 並自己判斷哪些結論過期了。
#
# 而搬進來的過程本身產出了八個更正,因為每一個繼承來的數字都被重新導出了一次:
#   1. 「6 個模組 932 行零測試」錯兩次:六個行數加起來是 1026,而六個裡有三個
#      確實被測試讀到。那個主張是用手拼的,而這正是這個 repo 想避免的失效模式。
#   2. 26.6% 過期了 —— 分母長到 34,794,現在是 25.8%。而更重要的是**那個百分比
#      是頁面上最弱的數字**:分母是整棵樹,所以在任何地方多寫測試都會讓它下降而
#      什麼都沒接上 —— 這一輪自己的普查就靠 1,042 行把它從 26.6% 推到 25.8%。
#      會乖乖表現的數字是接縫數(42,由閘維護)。
#   3. 「真實 Guardrails 延遲」被列在 /32 阻塞清單裡,而 T-K3 已經量了
#      (p50 415.8–435.4 ms)。一個做完的量測留在阻塞清單裡,就是一個阻塞變成
#      永久藉口的方式,所以它被移出並具名說明。
#   4. 749 ms 不是我們的數字,是第三方 client-side 的 n=15;我們自己量到的低約 44%。
#   5. 「不遷 tool-use」是錯的 —— agent_node.py:221 確實傳 toolConfig。真正的不變量
#      是「會讓身體動起來的東西是事後解析的文字標籤」,而工具邊界另立為 I8。
#   6. D1 原本寫「意外的、從不稽核的 containment」,而 EGRESS[GESTURE] 那一列
#      **宣告**了它(enforcer="body.gestures.GESTURES")。安全性質成立;丟掉的是
#      稽核軌跡。強制往下游搬了一跳,可觀測性在路上被丟掉了。
#   7. memory/rank_harness.py 被列成刪除候選、理由是「零測試」,而 tests/test_rank.py
#      import 它並斷言它的 JSON。前提是假的,R2 的那一項被移除。
#   8. tests/test_tools.py 有 38 個測試函式而**收集到 62 個案例**,而 doc_counts.py
#      對帳的是後者。寫 38 會是一個標籤與計算不符的數字。
#
# 這份清單由**與 base tree 對帳**產生,不是憑記憶列的:base 是
# r0a-wiring-census 的 f2b87315f9b3(tree e8f62364b79d,148 個 blob,truncated=false),
# 把工作樹每個檔案的 `git hash-object` 跟它比一次,得到 2 個變更 + 6 個新增;
# 扣掉刻意排除的 5 個之後是 5 行,再加上推送機制自己的兩行,總共 7 個 blob。
#
# 這一輪**疊在 #28 上**,不是從 main 開的,而這不是偏好:docs/design.md 通篇引用
# infra/dormant_seams.tsv 與 infra/wiring_census.py,而那兩個檔案只在
# r0a-wiring-census 上存在。從 main 開會產出一份引用不存在檔案的設計文件。
# #28 在 2026-08-25 仍是 open(base=main),查了才這樣寫的。
#
# 對出來的差集裡有五個檔案刻意不在清單上:daemon/miniaudio.h 與 daemon/oar-daemon
# 是廠商標頭與建置產物,infra/local.env 與 infra/ssh_config 帶帳號專屬值且 git-ignored,
# .push/message.txt 是這次推送的訊息本體。
#
# 兩個變更檔在 base tree 與磁碟上都是 100644,三個新增的在磁碟上也是 100644,
# 沒有 --allow-mode-change。
#
# ── 修訂(同一個 PR,分支 force 重推,parent 仍是 f2b87315f9b3)──────────────
# 第一次推上去之後,我把這份 PR **自己**的數字也重新導了一次 —— 因為「每一個數字
# 都要有導出過程」這條規則,對寫下它的那份文件也成立。三個是錯的:
#   9.  「六份研究文件(169 KB)+ 一份審視(22 KB)」:169 在兩種單位慣例下都不對
#       (實測 168.3 KiB / 172.4 kB),而總數 191 只有在 KiB 下成立(190.8 → 191)。
#       兩個 part 各自四捨五入之後**加不回**那個總數(169+22=191 只是因為 169 錯了 +1)。
#       改成只留一個可被導出的數字:「六份研究文件與一份設計審視,合計 **191 KiB**」。
#       六、一、191 三個事實各自可查,而且沒有「兩個 part 必須加得回總數」的問題。
#  10.  plan.md §3 寫「measured inventory 是 **14 files, 433 KB**(12 個在頂層)」——
#       而**這個 PR 自己**把 design.zh-TW.md 與 plan.md 加進 docs/,所以它落地的那棵樹
#       裡是 **16 files**(14 頂層 + 2 在 docs/evidence/)。一份在自己造成的樹上就已經
#       不成立的數字。位元總數整個拿掉(它不承載任何論證 —— 承載論證的是 14+2 這個
#       拆分,它證明非遞歸的 glob 會靜靜豁免 evidence 目錄),並且寫明 R0b-2 加
#       docs/INDEX.md 之後這個數字會在**同一個 PR** 裡動到 17。
#  11.  同一句的 433 KB:即使照原本 14 個檔案算也是 443.0 KiB / 454 kB,不是 433。
#
# 這三個不是繼承來的數字,是**這一輪自己寫下的**,而它們錯得很有意義:一份主張
# 「散文裡的數字按建構就是未被驗證的」的文件,自己帶了三個沒有導出過程的數字進來。
# 這正是 §7 第 2 條寫下的那個缺口(doc_counts.py 的 DOCS 不含這兩份文件)的**實證**,
# 而不只是一個理論上的可能。R0b-2 擴大 DOCS 時,新增的 pattern 就是讀這幾句
# (191 KiB、16 files),突變體是「改文件裡的數字並要求出現 finding」。
#
# 其餘每一個行數主張都重新導過而且**成立**:六個休眠模組 3,492 + 5,488 = 8,980、
# 整棵樹 34,794 行(80 個 .py)= 25.8%、三個零測試檔案 449 行、
# arch_render + test_architecture 1,748、perception+speech+gateway+body 四個目錄
# 全部 .py 共 **1,428**(九個檔案,不只節點檔)、store.py 1045、arch_render.py 1118,
# 以及 §5 表裡八個逐檔行數(213/140/96/219/137/221/175/89)全部相符。

# 唯一權威的設計陳述。七節:五個承諾各自接到哪一層、System 1/2 的分工與逼出它的
# 那個量測、不變量 I1–I8 的封閉清單(每一條指名失去它時會紅的測試)、缺陷 D1、
# EGRESS 出口表、§4 的三態分類、§5 導出的覆蓋率表、§6 四項人為阻塞、§7 防腐機制。
#
# §4 分三態而不是一句「不做」,是這份文件的形狀論證:被證偽(路由)、延後且有具名
# 前置條件(延遲遮蔽)、未被評估(離線可用性)。一份把「延後」寫成「否決」的文件,
# 會讓下一個讀者以為證據已經蓋棺。§4.4 另立一節列出**三條不得再被引用的主張**,
# 因為輪次是原文保留的,那意味著裡面的撤回必須被浮上來而不是留給人翻到第 12 頁。
#
# §7 的第 2 條是這份文件對自己最不客氣的一句:doc_counts.py 的 DOCS 是
# test-design.md + 兩份 README,**不含這個檔案**,所以它引用的 62 是手查的不是閘住的。
