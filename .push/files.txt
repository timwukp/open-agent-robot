# infra/doc_status.py 對目錄兩個方向對帳的閘、以及把 infra/doc_counts.py 的 DOCS

# 數字進來,而它們之所以活得下來,正是因為守衛的範圍不含那三份文件。
#
# 而擴大 DOCS 的方式本身是這一輪最值得寫的一件。第一版是「再加幾個 pattern」——
# 一份我記得的句子清單。改成兩個**導出**的檢查之後,它們在第一次執行就抓到三個
# 真的陳舊數字:
#   1. §0 表有 33 列,每一列都帶一個「L3 選到 N 個」而**沒有任何讀者**。現在那個
#      數字由一個走訪整張表的迴圈對 `pytest -m mutation` 的逐檔收集數對帳,
#      而它立刻報出 tests/test_consolidate.py 寫 13、突變層收 12
#      (查了原始碼:11 個具名突變體 + test_no_mutant_control = 12,那一列的
#      「12 個具名突變體」也高了一個),以及兩列**完全沒寫**總數。
#   2. 「沒寫總數」那兩列不是筆誤,是一個**被刪掉的突變體會留下的樣子** ——
#      所以四個分支都要出 finding:寫了但漂了、寫了但那一層收不到東西、
#      沒寫但那一層有東西、以及一列裡寫了兩個數(那時沒有任何單一數字被檢查)。
#      **未編號就是未被計數**;而 tests/test_deploy_path.py 的「17 個具名突變體 +
#      一個對照」與 test_redact_scan.py 的「8 個 + 無突變對照」讀者要自己加,
#      而閘不做算術,所以兩列都補上 18 與 10 這兩個總數本身。
#   3. 七個段落引用某個模組的案例數,同樣沒有讀者。現在由 PROSE_CASES 掃出來,
#      掃到零處是 finding —— 零代表句型被改寫了,而不是代表沒有問題。
#
# 一個讀者、一個格式:TABLE_ROW 被加寬成把散文那一格當 group 3 抓回來,
# 而**不是**在同一列上再加第二條 regex。兩條 regex 讀同一列,會在對方移動的時候
# 各自保持綠色。

# §0 表補上三個陳舊的 L3 總數與兩個缺的總數;§3 整段用這一輪的重新量測重寫。
# 這一輪的量測結果不是那些秒數,是「一個窄的 n=2 區間不是穩定性的證據」:
# 整套最早兩趟讀到 239.4 與 239.4(到小數第一位都一樣,寬度 0.0 s),
# 同一條指令在同一棵樹上再跑六趟,八趟合起來跨 137 s。
# 那個寬度殺掉了兩趟版本已經寫下的三個結論 —— 有負載時比較慢(第五趟 229.0 s
# 低於無負載的 239.4)、部分之和小於全體(兩半相加 230.1–310.9 整段落在區間裡)、
# 這一輪比上一輪慢(239.4 就在區間裡)。§3 因此在每個區間旁邊寫 n,
# 並寫下停止規則:活著的那個結論(L1 對 30 s 超標 3.1–4.0×)是一個數量級的差,
# 不需要第九趟;而任何尺度小於 137 s 的計時主張,在這台機器上這種負載下量不出來。
100644 docs/test-design.md
