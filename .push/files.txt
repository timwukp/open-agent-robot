# R1.1b — 那個唯一的寫入者從來沒有起來過,而普查把它後面的接縫報成「接上了」。
#
# 這不是計劃裡的一層。它是接 R1.2 的第一天發現的:`memory/memory_node.py` 被
# `infra/run_ec2.sh` 當**檔案**啟動,所以 `sys.path[0]` 是 `memory/`,而 `memory/`
# 裡面沒有 `memory` package —— `from memory import profile` 在**任何**工作目錄下都在
# `rclpy.init()` 之前 `ModuleNotFoundError`。另外四個被啟動的節點每一個都帶著那行
# `sys.path.insert`,只有這一個沒有。
#
# **誠實邊界,跟每一個 R1 的 PR 同一句:結構斷言證明線被宣告了,不證明訊息真的流過去。**
# 這一層加的那一句更強一點,而它一樣是靜態的:**這個行程連起來都起不來**。證明修好之後
# 卡片真的到得了,仍然是 L4,仍然需要 `/32`。
#
# 為什麼它自己一層,不塞進 R1.2:一個正確性修補不應該躺在還沒被 review 的功能接線底下。
# R1.1 的 PR 訊息說「卡片到得了跑著的機器人的提示」——那句話對原始碼是真的,對跑著的
# 機器人是假的,而這一層是把那句話變成真的那一個 commit。
#
# **一個假的 `reached` 是這支普查唯一必須不可能發生的方向,而它剛剛發生了。**
# `infra/wiring_census.py` 的 `aliases()` 自己的 docstring 寫著它解析的是
# `from <pkg> import <mod>`「**在一次 `sys.path` bootstrap 之後**」,而它從來沒有檢查過
# 那個 bootstrap 在不在。所以修補配一個閘:`bootstrap_findings()` 是第四個粒度,
# 兩邊都導出 —— 啟動集來自 runner 自己的表,package 集來自磁碟上的目錄,
# `.parent` 的個數由啟動表寫的路徑深度算出來。三種紅:那一行不存在、
# 在 import **之後**(import 被讀到時就執行)、深度不對。
# 而**這個檢查一個檔案都沒檢查到 → exit 3**,因為 `[]` 有兩個成因而它們印出來一模一樣。
#
# 三個具名突變體改的是**被啟動節點自己的原始碼**,不是登錄冊也不是普查,因為缺陷只可能
# 住在那裡;外加一個 T-N2 形式的差值:把 bootstrap 拿掉、再把 `bootstrap_findings`
# 拿掉,**普查對那棵起不來的樹報綠** —— 其他三個儀器一個都看不見它。
#
# 合成樹的 fixture 也跟著改:`_synthetic` 的 `app/main.py` 現在自己帶那三行 bootstrap,
# 因為不帶的話這個檢查會報它 —— **而且報得對**。這裡選的是改 fixture,不是教檢查跳過
# 合成樹:一個學會跳過測試用樹的檢查,它的洞就長成一個測試 fixture 的形狀。
#
# 順手記下一件關於散文的事:§2.N 那段「L3 選到 20 個」的**分項**加起來是 13,而**總數**
# 一直是對的。總數兩個都有閘(§0 表格那一格與 `L3 選到 N 個`),分項沒有任何閘,所以
# 那 4 個直接對真實樹斷言的案例從來沒有出現在那段散文裡。這一輪把 18 個逐項寫出來。
#
# 時間重新量過(這一節的規則要求每一輪都量):**這一輪 L3 的最小值從 133.8 升到 150.5**,
# 而按這一節自己的規則那不構成「變慢」的證據 —— 加跑趟數只可能讓最小值下降,只有下降是證據。
# 收尾的 load average 是 7.93 對上一輪的 3.8(2.1 倍),那是更可能的解釋,而**它是沒有量的**。
# 量這一輪順手抓到三件關於數字的事,三件都寫進 §3 而不是靜靜修掉:
#   (a) **秒數的慣例從來沒寫下來** —— §3 全部是 `/usr/bin/time -p` 的 real,不是 pytest
#       自己那行。兩者這一輪差 1.5–9.7 s,而前三棵樹用的是哪一個已經回不去確認了。
#   (b) 「L3 只要 60 秒」那個倍數 2.2–2.4 → **2.5–2.8**:散文還成立(「兩倍多」),數字過期了。
#   (c) §3 原本寫「整套這一輪沒有重新量」,而**推送前的閘跑了兩趟**(252.2 / 257.9 s)。
#       讀數一直在,只是沒人把它當量測記下來 —— 一句「沒量」比一個寬區間更容易留在文件裡。
#
